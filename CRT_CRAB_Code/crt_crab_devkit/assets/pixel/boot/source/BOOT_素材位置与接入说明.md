# BOOT · 素材位置与 Godot 接入说明

仓库：`Qisi3344/clawd-crt-tower`；工程：`CRT_CRAB_Code/crt_crab_devkit/`。
目标是屏内 2D 的 BOOT（`data/levels/boot_01.json`），不是外部 3D 电脑塔。现有地图 **1024×640**，单活动视口 **320×240**，相机跟随 X/Y。

|---|---|---|
| upper | 0,0,1024,112 | 维护灯带、悬吊线缆、风机、供电脊柱 |

## 2. 背景分层方案

**远景** `boot_far_continuous_1024x640.png`：1 张完整 1024×640 低对比背景。推荐 `z_index=-30`，在 `world_backdrop.gd` 为 BOOT 加专属分支。初版可**直接以世界坐标 1:1** 绘制并检验。若要视差，必须处理取样边界——使用完整底色覆盖视口，再做裁切采样/镜头偏移，不能露出透明空洞或越界重复。

**中景** `boot_mid_continuous_1024x640.png`：透明 PNG、世界坐标 1:1，建议 `z_index=-20`。这张不是平台、墙或机关碰撞层。大环形机器绘制在当前大厅地标周围，但要避免遮住推箱压板和门。图面含完整连贯的工业壁面，无需再切成 48px 宽小块循环。

**道具**：放在 `z_index=-4` 或适合的背景层，使用 `texture_filter=NEAREST`，整数像素坐标；图集 `boot_props_atlas_512x192.png` 可配合 `props_manifest.json` 用 AtlasTexture 取出。根据平台真实顶面与关键机关范围摆放，不能简单按每隔 64px 随机生成。

**概念图**：三张 reference 仅用于风格参照。图里有画出来的楼梯、平台、角色、提示文字、虚构交互设备，**禁止整图直接覆盖世界**。

## 4. 特别注意：不能覆盖真实游戏对象

保留 `data/levels/boot_01.json` 的 `platforms`、`ladders`、`spawns`、`blocks`、`plates`、`doors`、`chests`、`connections`；保留真实主任务、信号、机关行为和存档。背景不添加碰撞体、区域传送或新的隐形墙。

保持 ARCHIVE v2 已确认的工作方法：**连续环境图 + 远近景层次 + 少量专属道具 + 与真实平台材质协调**。不要重演曾被否决的“从大图硬截 3 块 → 48px 宽缩图 → 按列循环贴”的方法。视觉需要尽量接近概念图细致的像素游戏感；程序化底稿若显得过于简陋，可以整层重新绘制，但不要把不合适的小块强行拼接。

建议 BOOT 地面与平台颜色以深蓝灰为主，细条薄荷绿指示灯为点缀；重要碰撞平台依然要比背景更可辨识。不要让角色、宝箱、真实压力板、蓝色能源柱与背景设备混为一体。

## 5. 交付边界与验收

包内 PNG 已生成，并非真实游戏实机截图；没有在这次素材制作过程中实际改动 GitHub 或运行 Godot。Codex 接入时需提供：BOOT 起点、中央大厅、上层维护、下层线路井的实机截图；进出 ARCHIVE、推箱、爬梯、回访/存档检查；左右镜头边缘与视差边界检查。**不因这一关美术改动扩大需求。**
