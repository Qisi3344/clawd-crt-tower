# RECYCLE · 回收站 美术位置与 Godot 接入说明

以仓库最新 `data/levels/recycle_01.json` 为准，1024×768，活动 CRT 320×240：

| ID | 位置 | 氛围 | 核心视觉 |
|---|---|---|---|
| `upper_left` | x 0–512 / y 0–288 | 吊装观察台 | 远处吊装起重机、工业护栏影子、废 CRT 缓存架 |
| `cache` | x 512–1024 / y 0–288 | 数据重构吊台 | 发光重构设施、信息读头、回收铭牌 |
| `sorter` | x 0–512 / y 288–528 | 中央分拣大厅 | 可逆输送带、压机、机械分拣设备 |

| `scrap` | x 352–512 / y 528–768 | 地下废料坑 | 废 CRT、断裂键盘、零件箱堆积（注意可读性） |

- 可逆输送带 `(192,448)`；SAFE STOP `(112,448)`；压机 `(288,448)`。
- 主磁吸井 `(680,576)`，控制点 `(672,688)`；暗道磁吸 `(176,576)`，控制点 `(80,688)`。
- 三片数据 `(400,672)`、`(592,592)`、`(608,192)`；重构终端 `(768,208)`。
- 真实梯子 X：80 / 448 / 592 / 656 / 976。不可额外画出没有碰撞的可爬梯。

## B. 图层

1. `far.png`：世界远景。可以整图绘制后做约 0.1–0.15 视差样板，但采样不得越界。如果要分层视差，必须检查四角与上下三层。
2. `mid-continuous.png`：当前世界坐标 **1:1** 透明中景。在 `SideWorld` 地板/玩家/机关之后；与地图物理层分开，不能替代真实地形。
3. `props`：按物件实际接触点定位的透明精灵。每件初始 64×64 画布，透明边距保留方便统一计算锚点；允许按实测更改尺寸，不要无脑将所有物件放大。
4. 原地板：由游戏已知 `platforms` 形状和碰撞继续生成，可改视觉皮肤，**不能更改碰撞体**。包内的 16px 瓦片仅是材质风格参考。
5. 动画（代码实现）：传送带齿轮慢速、远处指示灯、废屏微弱雪花、磁吸设备局部反馈。不要让纯装饰抢真机关注意力。

## C. 道具建议

- 上层（`upper_left` / `cache`）：01 CRT 堆、02 废料箱、07 吊钩、09 警戒路障、10 旧数据匣。
- 中层（`sorter`）：02 废料箱、03 线缆卷轴、04 破损键盘、08 分拣桶、09 警戒路障、12 维修终端。
- 下层（`scrap` / `tunnel` / `well`）：01 CRT 堆、05 裂屏显示器、06 电子废料堆、10 数据匣、11 管道弯头。
- 右侧竖井：11 管道弯头、12 维修终端与低密度电缆。

全部道具**仅作装饰无碰撞**。不得把装饰终端放在真终端旁边造成可交互误判，也不要把道具盖住箱石、宝箱、晶体或压板。道具布局不要等间距重复，允许改动样板位置。限制覆盖量，给机身与主角留视觉空间。

## D. 素材技术提示

- 本包 `far.png` / `mid-continuous.png` 是依据真实地图坐标绘制的基础画面，不是可直接上线的完整实机布景。审美请以 `source/` 的概念图为方向深化，但不要将其截成矩形片循环。
- Godot `texture_filter = CanvasItem.TEXTURE_FILTER_NEAREST`；原世界 1024×768 与视口 320×240 之间保持整数像素坐标。
- 从 `game/props/*.png` 加载逐张 PNG 更易检查；需要压缩绘制可用 `game/props-atlas.png` 及 `manifest.json`。
- 对照 `scripts/world_backdrop.gd` 当前 BOOT 和 ARCHIVE 分支，增加 RECYCLE 独立分支，不可改写已有两关。
- 如要参照 ARCHIVE v2 中的连续美术合成，请查看 `docs/ARCHIVE_ART_V2.md`；不要复用已被否决的 archive v1 48px 橱柜裁片方案。

## E. 验收

以真实游戏运行结果为准：中层分拣、上层重构吊台、下层磁吸井、地下废料坑、右侧维护竖井各至少截图 1 张。要求连续场景、真地面一致性、视差边缘无黑洞、物件不穿模、不影响机台 320×240 画面。至少一段普通输入行走录像；验证输送带、压机、磁吸、收集数据片、重构流程。程序专项通过并不代表美术完美，必须逐张视觉检查。
