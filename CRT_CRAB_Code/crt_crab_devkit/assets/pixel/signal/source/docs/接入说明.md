# SIGNAL · 信号中心美术接入说明

版本：v1.0；仓库快照核对：2026-11-08。

## 1. 设计目标

SIGNAL 是真正的「通信节点」，不是 BOOT 那种供电机房，也不是空旷太空场景。三种信号路径的视觉语言必须不同，但在同一个青蓝—冷紫色工业室内世界里自然连接。

- **A：真实源信号塔** — 左上，稳定青色圆环信号柱，少量放射状波纹；与 ARCHIVE 持续压板逻辑相关。
- **B：继电蜂桥** — 中间偏右，紫青色脉冲环、波形分析屏、导电小节点，标示暂时性供电。
- **C：光纤汇流井** — 右上，竖向纤维束、三层插口、高亮青色光线，逐步向上接到总线。
- **HUB：中央诊断台** — 中层左边，是三路信号状态的理解中心，以雷达波形 / 诊断设备作为背景识别。
- **绝缘水道** — 最下面，深青色水面、绝缘管、电位警告标志，少量反射，避免让水看起来是一条可走平台。

### 4. 具体素材放在哪

**远景**：`game/far.png` 是 768×576，深处通信塔、缆线与非可行走的影子结构。可用 0.15 倍 camera.position 作纹理源坐标，整张不循环。

**连续中景**：`game/mid-continuous.png` 是 1024×768，适合 Godot 用世界坐标采样 `draw_texture_rect_region(mid,view,view)`；少量透明观察窗透出远景。不要再次裁成小墙块重复。

**地形材质**：三张世界宽度 1024 的连续条带，按每个实际碰撞平台的位置采样，不能每段从 x=0 重复铺。平台本体的颜色可以使用与条带统一的深蓝灰色。原物理碰撞完全不变。

**独立道具**：共 12 件，PNG 与 `props-atlas.png` 可二选一。道具建议坐标见 `source/asset_manifest.json` 中的 `suggested_noninteractive_placements`，这些是视觉建议，不是碰撞安全已经通过的证明；Codex 必须查看站立点与操作距离，再确定最终位置。

### 5. 建议 Godot 接入方向（伪码）

```gdscript
# scripts/world_backdrop.gd 在 world.screen_id == "SIGNAL" 的分支
# 背景节点保持原 z_index = -10；素材与角色同属 320x240 视口。
var signal_far = load("res://assets/pixel/signal/game/far.png")
var signal_mid = load("res://assets/pixel/signal/game/mid-continuous.png")
# 已有 view 是与世界相交后的 Rect2，单位为世界像素
# 以下只表示绘制策略，请结合现有 _ready/_draw 并避免每帧重复 load
# draw_texture_rect_region(signal_far, view, Rect2(view.position * 0.15, view.size))
# draw_texture_rect_region(signal_mid, view, view)
```

注意：两层在代码里都应该由已有 bg `Node2D` 绘制；不是造两个 Viewport，避免扩大渲染开销。平台材质与道具应该走独立的非碰撞视觉节点。保留 `side_world.gd` 中原有物理对象；只有 SIGNAL 才跳过旧 `PixelArt.tile` 的视觉填砖，其他关仍按原分支运行。

### 6. 美术验收与范围

视觉检查覆盖同一张世界的 A 上层、HUB、B 继电蜂区、C 竖井、底层绝缘水道与右边界：中景连续不漏底、立面不断层，角色仍比背景更醒目；无假梯子/假平台；传送门和危险机关醒目；玩家上爬、回环、沿水道移动时背景不抖、不露空洞。

需要 Godot 原生截屏证明实机效果，不得用 `preview/SCENE_MOCKUP_NOT_GAME.png` 冒充游戏运行画面。自动 QA 通过不能代表视觉审美合格。

本包仅供 Codex 集成，不声明已在 Godot 运行、也不包含关卡或存档改动。
