# 给 Codex：只集成 SIGNAL 信号中心美术（直接执行）

仓库：`Qisi3344/clawd-crt-tower`，Godot 工程：`CRT_CRAB_Code/crt_crab_devkit/`。

请读取本包 `README_先看.md`、`docs/接入说明.md`、`source/asset_manifest.json`，并检查工程最新 `data/levels/signal_01.json`、`scripts/world_backdrop.gd`、`scripts/side_world.gd`。**直接完成接入并运行验证，不要只产出建议报告。**

本轮唯一目标：把屏幕内部第 05 关 SIGNAL 的背景与道具换成连续、有辨识度的青蓝通信中心；只做美术层。

## 实施顺序

1. 将 `game/` 的远景、中景、地面条带、12 件道具复制到 `res://assets/pixel/signal/game/`，遵守 Godot 的 import 与最近邻过滤。
2. 在 `world_backdrop.gd` 中增加 SIGNAL 专属分支：远景低速视差、中景用 1024×768 世界坐标连续绘制，利用透明观察窗透出远景；**禁止裁成小矩形循环贴**。禁止把 `reference/` 和 `preview/` 的图片用作游戏背景。
3. 地板只改视觉贴图：按世界 X 连续采样 `terrain-16/32/48.png`，沿真实 `platforms` 生成地表。物理碰撞和单向跳台仍保留原数据。不要出现断开的拼贴地砖。
4. 将 `props` 装饰按 A/B/C/水道主题固定摆放；建议坐标在 JSON，但必须检查机关、梯子和玩家活动空间，必要时调整；道具**全部无碰撞**，不可模拟真实可交互按钮。
5. A、B、C 三路地标视觉不同；核心状态变化若要与真实 flags 联动，仅作小范围灯效，不改动电路机制和旗标。不得更改现有六关地形、传送、宝箱、碰撞、角色和存档逻辑。
6. 原生 Godot 运行回归，输出真实 320×240 视口的 A 上层、HUB 中层、B 蜂桥、C 竖井、下层水道至少五处截图，以及至少一段移动中检查视差的视频或连贯截图。若需要生成综合展示图请单独标注“非游戏截图”。

## 必须规避的已知失败

- 不许把 AI 概念海报整张贴游戏或裁海报窗口、栏杆、梯子当背景。
- 不许对同一张图每隔 48/60px 重复铺贴，不能留矩形边框和墙面接缝。
- 不许用背景画出假梯子/假平台/假的可操作终端。
- 不许用太亮的霓虹、粒子覆盖真实 A、B、C 机关。
- 不许从绘画概念里新增玩法和解谜，别顺手重构这关。
- 文档或单元测试通过不能替代实机视觉验收。

如需要美术微调，允许重绘或自然修补 `game/mid-continuous.png`；保留原美术文件和改动说明。**不需要反馈确认，做完整个 SIGNAL 再汇报。**
