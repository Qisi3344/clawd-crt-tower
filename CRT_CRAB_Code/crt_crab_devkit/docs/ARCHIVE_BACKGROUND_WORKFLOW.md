# ARCHIVE 地图背景制作思路

记录日期：2026-11-08。对应连续环境重做提交 `b5d8eca`，机壳暗部微调提交 `2e8aa04`。这份记录解释制作判断和后续复用方法；实机截图、回归结果见 [v2 验证报告](ARCHIVE_ART_V2.md)，具体生成提示词见 [制作源记录](../assets/pixel/archive/source/CONTINUOUS_V2_PROMPTS.md)。

## 先确定真实空间，再画背景

这关的世界是 1024×640，玩家每次只能看到其中 320×240。背景既要在一个小窗口里有可读性，也要在横向移动和上下攀爬时属于同一座建筑。

先读取 `data/levels/archive_01.json`，把碰撞平台、真实梯子和机关占位画成布局参考，生成工具是 `tools/archive_layout_guide.gd`。其中平台、梯子、机关和观察窗建议区域用不同颜色区分。这张图只用于约束制作，不进入游戏。

三条主要地面高度是 Y=64、208、448，分别组织上层检索桥、中层重压大厅、下层破损记录仓。小平台、单向通行区、推石路线和传送点沿用原数据。画面应当解释这些既有空间，避免美术反过来暗示玩家去走不存在的路。

## 旧版为什么需要撤掉

旧版把完整中景里的三段柜墙裁成矩形，再缩到 48px 宽、每隔 60px 铺一块。原图里的光照、柜体边缘和管线各自属于原来的建筑上下文，裁开之后无法自然连接。循环排列又把三种柜体的重复和块间空隙放大了。

因此这次删除了三张柜墙贴片及循环代码，改为制作完整建筑立面。没有通过模糊边缘、降低中景透明度或补更多零碎柜体来处理接缝。

## 四类画面各自负责什么

| 层 | 负责的内容 | 放置依据 |
|---|---|---|
| 远景 | 更深处的档案空间，提供纵深 | 镜头位置的 0.15 倍采样，单图不循环 |
| 连续中景 | 柜墙、建筑竖柱、弯管、嵌入式柜体、墙灯、观察窗框 | 整幅 1024×640 世界坐标 |
| 地形表面 | 玩家能站立的平台和地面材质 | 现有碰撞矩形的准确位置与尺寸 |
| 独立道具 | 推车、纸箱、终端、卷轴、灯、封存箱等局部叙事 | 固定锚点、真实地面或真实悬挂结构 |

角色、宝箱、压力板、可推石块、真实梯子和传送光柱继续由原有玩法对象绘制。装饰位于它们后方，保持交互轮廓清楚。

## 连续中景怎样制作

使用仓库保存的原始高清中景、远景作为美术参考，同时提供真实关卡布局。内置 image_gen 生成与编辑完整立面，让柜体尺寸变化、墙板、竖向结构和管线构成连续建筑；使用紫灰金属与暖色灯光保持原素材的档案库气质。

生成结果并不能直接当成成品。第一轮仍画出了没有碰撞的长横梁和桥面，必须再编辑移除，补回柜墙、墙板和竖向结构。实际平台另外绘制，这样任何长横向可站立表面都有明确的地形来源。

最终选定源为 `assets/pixel/archive/source/mid-continuous-v2.png`，编译时整幅缩放一次到 1024×640，输出 `game/mid-continuous.png`。运行时按世界坐标采样同一张图，不把柜墙拆成重复单元。单幅方案适合当前世界尺寸；未来若关卡显著扩大，应重新评估纹理预算和分区方案，不能直接把所有关卡都做成无限增大的整图。

四个圆角观察窗用于露出远景。图像工具两次把透明区域画成了棋盘格，实际 alpha 仍接近不透明。编译器从四个窗内种子点出发，只清除连通的中性亮色窗洞，并把其余建筑像素设为全不透明，再进行整图缩放。这里处理的是明确的窗洞遮罩，不能扩展成对整张墙面做亮色抠图。更换源图时必须重新检查种子位置、阈值和窗框边缘，避免误抠灯光或漏出棋盘格。

## 地面为什么单独制作

旧的 16px 重复砖和新柜墙在细节尺度、轮廓与配色上不一致。重新制作窄钢梁、厚基础两种长条材质，并编译成 1024×16、1024×32、1024×48 三种尺寸。

`scripts/archive_terrain.gd` 从现有平台数据生成视觉表面。同高度、同厚度且首尾相接的矩形只在绘制层合并，然后按世界 X 坐标取材质。例如相邻两段应分别采样材质中对应的位置，而不是每遇到一个碰撞分段就从纹理左端重画。这样不会把隐藏的碰撞分段表现成地面断缝。

`side_world.gd` 仍然先创建原有碰撞体，仅在 ARCHIVE 跳过旧砖块绘制。没有合并物理碰撞，也没有改变单向平台、梯子通行或推石行为。其他五关继续原来的视觉分支。

## 独立道具怎样融入

保留 12 类身份，收拢为 15 处固定摆放，不随机撒满墙面。检索区放柜体和挂档，大厅放推车与归档工位，下层放卷轴、破损终端、散落记录与封存箱。

站立道具以底部对齐真实平台，悬挂道具连接现有顶面。支撑柱连接桥底和地面；装饰梯放在墙面收纳框内，避免被误认作可攀梯。每次移动道具都要检查机关操作路径和角色经过时的遮挡关系，不能只看静态构图是否丰满。

## 验收顺序与保留证据

1. 检查编译资源尺寸、窗洞 alpha、12 类身份和道具落地锚点，确认没有重新引入柜墙贴片。
2. 实际启动 Godot，用动作输入走到上、中、下层，操作攻击、推石和攀梯，保留录像和完整机台截图。
3. 单独用镜头夹具覆盖各层全宽与四角。全宽图来自 320×240 GPU 读回的无缩放拼接，并非扩大游戏视口，也不把镜头定位当成玩家正常通关。
4. 逐图检查矩形边缘、柜体重复、管线去向、平台表面连续性、道具脚底，以及任何可能被误认作可走路面的装饰。
5. 再核对六关、宝箱、机关信号与存档回归。程序通过和画面连贯分别验收；前者不能代替后者。

本轮证据和报告位于 `docs/archive_art_v2_evidence/`。桌面实机检查已经完成，手机硬件性能与用户主观验收不能据此推定完成。旧版接入报告保留为历史，并已明确标记被 v2 替代。

## 迁移到开放场景时的修正

后续 POP-UP 的返工补充：连续环境不等于连续墙面。ARCHIVE 的柜墙组织适合档案库，但不能把开放城市的天空、独立装置、维修间和水面都改成墙。迁移这套方法时先列出参考图的空间与标志物清单，逐项检查实机有没有保留；“没有裁片接缝”只说明合成连续，不能证明场景还原正确。避免假平台应通过准确的真实地形、背景纵深和设备落地来处理，不能删掉所有非墙面内容。

视差背景也不能直接当作静态世界全景来拼接：各镜头看到同一远景标志物的位置不同，拼接会重复显示标志物。开放城市应提供独立镜头和行走录像来验收远近层次，拼接图只用于地形、前景结构检查并明确标注这一限制。

## 后续机壳补光是独立调整

地图内容在 2D 视口内，机壳属于外部 3D 场景。用户随后指出背光机壳过黑，处理时调整的是外部环境补光（0.28 → 0.38）与深色型号机壳底色（`293340` → `344150`），保留主光和轮廓光。没有为了提亮外壳去提高地图亮度。判断画面发黑时，先确认问题属于屏内地图、机壳材质还是外部打光，分别处理。

后续迭代入口：`source/` 保留制作源与提示词；`tools/build_archive_art.gd` 负责可重复编译；`tools/install_archive_art.ps1` 负责编译、导入；`tools/inspect_archive_art.py` 负责资源核对；`tests/archive_art_qa.gd` 负责实机穿行和截图。重新绘图后要完整走一遍编译、资源检查与实机观察，不能仅替换 PNG 就沿用旧截图作为新结果。
