## 0. 一句话概念与设计目标

将目前「孤立在测试空间中的 CRT 电脑塔」升级为一座**被地下复古电子街区围绕的神秘中央终端**：左边是狭小的维修工位，右边是停业的街机/贩卖机角，后方是供电与旧服务器设施，上方是横梁、桥架和指示牌。整个区域像有过人类活动，但现在主要由机器自行运行。

这不是创造一个可步行的开放街区。**外部场景是氛围舞台，不是螃蟹可行动的地形**。真正的关卡仍在 CRT 的 2D 屏幕里。

### 本轮目标

1. 电脑塔依旧是画面绝对主角，新增环境只负责空间纵深、生活痕迹与世界观。
2. 使用确实能下载且授权清晰的 Sketchfab 模型补足主要硬表面物件；不再用重复基础立方体充当所有家具。
3. 正面、背面、左右、仰视/顶视均有可信的结构与层次，镜头不会被背景和道具挡住。
4. 统一为「潮酷、复古、稍有诡异感」的视觉体系，而非霓虹过载或高度写实的赛博朋克。
5. 保证 BOOT/ARCHIVE、跨屏镜头、2D 字体可读性、暂停、存档与性能不回退。

### 不可违背的硬规则

- 保留**三层以上、360°错落堆叠的 12 台 CRT 核心构图**；不能变为一面电脑墙。
- 螃蟹只能在 CRT **屏幕内部 2D 像素关卡**活动；不能走到外部底座、维修台、街道或实体显示器表面。
- 屏幕游玩时，螃蟹与谜题必须保持清晰；环境道具、反射、贴纸、装饰都不得挡住 active CRT。
- 外围布景不引入新的玩家控制、物理闯关或独立可玩地图。
- 不复制《绝区零》的 UI、角色、商标、招牌或其他受保护设计；只学习「潮流街头 × 复古工业 × 图形叙事」的设计方法。
- 禁止 Flash 感廉价平面 SVG、无厚度立方体排排站、随机英文大字贴纸、毫无支撑的悬浮线缆、散乱粒子和过度 Bloom。

## 2. 整体艺术方向：RETRO AFTER HOURS

**世界叙事**：这是一个已经打烊的旧电子维修/电玩集散站。电脑塔像从废弃设备中被不断改装出来的公共终端。有人使用过这些机器，留下了标签、维修记录、数据线、软盘和饮料售卖机，但现在只剩屏幕还亮着。

**质感关键词**：利落厚实的低模轮廓、薄塑料外壳、喷漆金属、亚光机柜、软胶电缆、丝网印刷标签、少量潮流字体、克制的旧化。**不要**大面积锈蚀、脏污、油腻的写实末日废土。

**配色（沿用旧场景书）**：

| 角色 | 色值 | 用途 |
|---|---|---|
| 背景暗部 | `#151923` | 空间深处、天花背阴 |
| 工业石墨 | `#293340` | 地台、梁柱、背墙 |
| 复古米白 | `#DDD4C2` | 机壳、维修配件 |
| 酸柠黄 | `#DCE65B` | 主品牌标签、功能视觉指示 |
| 电子青 | `#54CFC3` | 电源灯、信号、侧向辅助光 |
| 莓果粉 | `#EA5985` | 街机区、次要招牌 |
| 旧灰绿 | `#87958D` | 旧设备、钣金及架体 |

配色是**统一重着色目标**，不是每件物体都必须涂成鲜艳颜色。以石墨/米白为大面积基础，黄、青、粉控制在局部。一眼看过去应先看到 CRT 塔，再看到外围街角。

**视觉注意力预算（不是几何面积）**：电脑塔 65%，外部布景 25%，灯光/小动态 10%。优先让中央塔的最高亮度、对比度与识别度更强。

## 3. 四周空间规划

### 3.1 位置示意（俯视，非游戏可走地图）

```text
                     后 / BACK
       ┌────────────────────────────────┐
       │ 供电/服务器区                  │
       │ [配电箱] [服务器] [线缆桥架]    │
       │                                │
 左侧  │  维修区     ╔════════╗   电玩角 │  右侧
 LEFT  │ [工作台]    ║  CRT   ║  [街机]  │ RIGHT
       │ [工具架]    ║ TOWER  ║  [贩卖机]│
       │ [零件箱]    ╚════════╝  [灯牌]  │
       │                                │
       │    前方：保持镜头观察净空       │
       └────────────────────────────────┘
                    前 / FRONT

顶部：悬梁、灯轨、少量风管和导线桥架
外圈：简化建筑轮廓 / 暗色屏障 / 局部灯箱
```

“左右/前后”须在 Codex 实际打开游戏后，按主菜单默认镜头重新绑定，不允许直接把上图当世界坐标写死。

### 3.2 中央：CRT 塔核心展示区

- 不调整核心塔的三层 360°结构；保留现有机壳、可玩屏幕、端口和控制路径。
- 塔最外缘至第一层外围大型模型之间留**镜头安全区**：需根据目前相机轨迹、视锥和模型边界实测确定，不能直接套固定米数。
- 已有工业底座边框、线缆、软盘箱等继续保留；如果与新增物件重叠，应移动/整合，不应重复复制两套。
- 中央塔附近只保留稀疏的地面贴纸和接线结构，避免屏幕下方杂物堆积。

### 3.3 左侧：REPAIR BAY / 维修工位

**视觉故事**：有人拆装、维修、记录过这些老式终端。

主物件：

1. 一张**有实体结构**的低模金属工作台（不要方块桌腿拼凑）。
2. 一套金属置物架，陈列旧 CRT 零件、键盘、废电路板、软盘盒（小件可程序化或已有复古电子包复用）。
3. 一个斜挂的维修灯/手电式光源，照亮工作台的一侧。
4. 一个原创纸质工单牌：`CRT SERVICE / UNIT 07`。
5. 局部散落键帽、导线、螺丝盒，数量控制在可识别范围。

**摆放**：工作台偏向外圈，并斜转约 10–25° 朝中央塔；货架贴近背景墙/背板；从前侧看能识别“正在维修”，从后侧看有正常背板厚度。所有抽屉/桌腿/桌面支架必须落地或连接结构。

**动画**：桌面维修灯可轻微闪动，但不要随机强闪；可选风扇缓慢转动。

### 3.4 右侧：ARCADE CORNER / 旧电玩街角

**视觉故事**：一个曾经热闹、现在停业的微型电玩角。

主物件：

1. 两台不同面向的低模街机，显示**原创**像素演示画面。
2. 一台复古贩卖机，使用原创标签（如 `BYTE SODA`），不保留第三方品牌素材。
3. 一组灯箱、贴纸、票据或小号游戏海报，附着在**有厚度的**支架或墙面上。
4. 一段街机区边缘的软胶地垫/地面图案，区别于维修区。

**摆放**：街机高低错落，不形成整齐一排；贩卖机在远侧做第二视觉焦点。街机不能比中央塔更亮，也不得让玩家误以为可操控街机代替 CRT 屏幕关卡。

**动画**：一台街机低频切换像素画面、另一台显示待机波形；灯箱亮度缓慢呼吸。后台动画可按距离和视角降频。

### 3.5 后侧：POWER & STORAGE / 供电与存储区

**视觉故事**：电脑塔所有显示器电源/网络从这里供给。

主物件：

1. 1–2 个低模服务器机柜；适当错开前后深度。
2. 一个可辨识的配电箱，位于画面后侧但不贴着 CRT 屏幕。
3. 一组沿上缘或墙体转弯的模块化管道。
4. 由塔上的真实接口/已有线束延伸到配电结构的线缆，路径清晰；避免凭空起止。
5. 一块原创 `POWER DISTRIBUTION / LINK STABLE` 标识，作为机械世界观的信息。

**摆放**：主供电面板靠近背部空间，适当提升层级，使 360°旋转时能看出纵深；不能在塔后方叠一堵同高度的黑墙吞掉 CRT 轮廓。

**动画**：服务器指示灯随机缓慢闪烁、个别散热风扇旋转，频率克制；配电箱不要做高频电弧特效。

### 3.6 顶部与远景

- 顶部：2–3 根横梁、少量吊挂灯牌、桥架与低面数通风管，保留电脑塔顶部完整剪影。
- 远景：暗色半围合工业结构，可用简化低模；**不建立完整建筑街区**，避免工作量暴涨。
- 地面：把测试网格感收束为工业地台、拼接板、发光标识与功能分区；地板不是可走地图。
- 背景不应喧宾夺主，不应让玩家疑惑“为什么这部分不能走过去”。

## 5. 素材落地流程（不能只复制下载链接）

### 5.1 下载与登记

每个候选先确认：页面允许下载 → 当前许可/作者与素材是否有附加限制 → 登录获取 → 解包 → 记录原始模型文件和贴图路径 → 快速预览 → 再决定正式导入。

下载失败时，记录 `BLOCKED_DOWNLOAD`，附原因与待人工下载页面；不要用其他无授权页面镜像替代，也不要标为成功。

### 5.2 Godot 导入规范

- 优先采用 `.glb` / `.gltf`，避免运行时联网取模型。
- 统一尺寸、坐标轴、朝向、pivot；原始导入资源与游戏内优化版分离存放。
- 为每个资产建立**独立可实例化场景**（如 `repair_workbench.tscn`、`arcade_cabinet.tscn`），不要直接散放进主场景且无法统一维护。
- 对过度写实贴图进行统一明暗、粗糙度、色相调整；必要时简化法线与多余透明面。
- 大纹理优先压缩或降采样，外部布景普通小道具不要使用 4K 材质。
- 所有第三方模型保留可追溯元数据，防止之后再次扫描资产时丢失来源。

## 6. 图形、标识与镜头规则

### 6.1 标识系统

原创短字样示例：`REPAIR BAY 07`、`BYTE SODA`、`GAME OVER?`、`SIGNAL STORAGE`、`PORT ACCESS`、`NO USER DETECTED`。采取大字少量、细字克制、编号有实际空间意义的设计；不要给每个面都贴随机标语。

招牌使用具有物理厚度的卡槽、薄金属板或灯箱，靠材质与结构而不是扁平大 SVG 平面贴图营造质感；图案本身可用原创纹理贴图与局部 Decal。

### 6.2 灯光分工

- CRT 活动屏幕：最强识别焦点；屏幕本身必须可读。
- 维修工位：低强度冷白定向小灯，提亮工位轮廓。
- 电玩角：青/粉局部灯光，强度低于当前 CRT。
- 后侧供电区：黄绿点光源指示灯，不使用满屏大量实时阴影灯。
- 背景总体偏暗但要能看出空间边界；避免黑到只剩几盏霓虹灯。
- 关闭 Bloom 时必须依然好看；特效只能锦上添花，不能掩盖粗糙建模。

### 6.3 摄像机与遮挡

- **游玩模式**：外部 3D 镜头聚焦正在运行的 CRT，内部 Camera2D 仍只跟随屏幕里的像素螃蟹；不要把这两个镜头逻辑混成同一个 3D 追尾相机。
- **阵列观察（Tab）**：允许 360°旋转，新增建筑/设备在任何方位不得遮住主要 CRT 阵列过久。
- **跨屏过渡**：相机沿电脑塔移动到下一个真实 CRT；若背景梁柱/街机挡镜头，应通过遮挡淡出、隐藏或重新布置解决，而不是让镜头穿模。
- 外围道具**不参与输入碰撞/互动**，不拦截 E / K / J / Tab / 鼠标事件。
- 如出现窄 CRT 4:3 屏幕适配问题，以仓库现有的 320×240 实现为准，不将其强行拉伸成 16:9。

## 7. 动态环境与音效（本轮只做轻量级）

允许增加：

- 维修小风扇缓慢旋转；
- 服务器灯或网络状态灯低频跳变；
- 贩卖机/街机待机画面稀疏切换；
- 极弱的管道振动、CRT 嗡鸣、工业空气声。

禁止：大量飞舞粒子、烟雾团、闪瞎眼的警告灯、持续闪烁的故障特效、无意义的随机运动。音乐以游戏内已有 BGM 管理为准，不要此阶段擅自添加商业歌曲或自动播放高音量音效；玩家进入 2D 关卡时声音层次优先服务玩法。

## 8. 性能与质量控制

目前仓库 `IMPLEMENTATION_PROGRESS.md` 提到在 RTX 5060 Ti 上的离屏绘制+读回采样数据；**这些不是交互游戏的稳定 FPS 基准**。实施前需在同一环境重新测定基线，再记录每阶段新场景的变化。

**软预算（有依据可调整并记录原因）**：

- 在最初 5 套 P0 模型构成的样板中，原则上不添加多个高面数主物件；目标为所有新增可见外围网格合计约 `≤ 60k tris`（以相机最差可见方向为准，优先保持更低）。
- 装饰纹理以 512/1024 为主，核心焦点按需 2048；重复物体尽量共享材质与纹理。
- 静态外部道具不启用不必要的碰撞体、AI 或每帧脚本处理；共享网格/材质，远距离可降精度。
- 仅对必要的关键光源开启动态阴影；纯装饰的小灯优先使用自发光材质。
- 新场景对同硬件、同分辨率、同路径的实际性能回退目标控制在约 10–15% 范围内；若超过，先降重复绘制、灯光和材质开销，不能直接牺牲 active 屏幕的更新与可读性。
- 不允许为了性能，把背景直接替换成 2D 假墙或无厚度廉价轮廓；可以有层次化简化，但需要三维深度。

若上述预算影响画质，Codex 应先提供成本数据与对比截图，再决定折中方案；数字为开发管理目标，不是已经测得的完成事实。

## 9. 分阶段开发与可交付结果

### E0｜快照/回归基线（必须先做）

1. 拉取最新 `main`，确认分支/commit、引擎版本和启动命令。
2. 本地启动游戏并录制/截取当前正面、背面、左右、顶视及 BOOT/ARCHIVE 活跃屏幕画面。
3. 使用仓库已有 QA（例如 `--qa`）验证目前两屏可玩，记录结果和帧耗/显存或内存；禁止覆盖正式玩家存档。
4. 查清 `ExteriorDressing`、`MonitorDevice`、3D shell 镜头与场景加载边界，备份/提交回退点。

**交付**：`ENVIRONMENT_QA.md` 中的基线和画面文件路径。

### E1｜P0 资产获取与完整度样板

1. 优先验证并导入 `SF-01/02/03/04` 四项，建立独立模型实例。
2. 搭建**维修区一侧 + 供电区一角 + 电玩区一小角**，不先铺满整片空间。
3. 配一套统一材质和两个主色点缀，制作完整的“未打烊过/被使用过”的生活痕迹。
4. 与电脑塔一起拍 3 张同角度对照图；若主要道具视觉太写实，先调色/材质再继续。

**通过标准**：中央塔仍最抢眼，外围已显著不再像空旷测试场；没有漂浮物、模型穿模或阻挡游玩的 CRT。

### E2｜完整 360° 四区搭建

1. 延展左维修、右电玩、后供电、上部管道/灯轨。
2. 按需要再导入 `SF-05~08`，不要为了填满场景而全部购买/导入。
3. 添加少量原创空间标识与生活小件；保证每组道具有明确功能关系。
4. 正/后/左/右/顶部五视图检查空间平衡、支撑关系及远近层次。

**通过标准**：五个角度均可辨主塔轮廓，环境没有明显空洞或重复贴图墙，也不喧宾夺主。

### E3｜灯光、过渡与微动态

1. 调整屏幕溢光和工位/电玩/供电三种光色；关闭 Bloom 也要保持质感。
2. 加入最多 3–4 种低成本微动态，提供开关。
3. 调整跨屏转场的遮挡处理，以及 Tab 观察模式的相机边界。
4. 复测两屏关卡、界面、存档和转场，消除新增严重错误。

**通过标准**：屏幕内螃蟹始终可见，穿梭转场无卡死/穿模，关卡输入不被装饰抢走。

### E4｜优化、署名与交付

1. 合并模型材质或实例、优化图片/渲染开销。
2. 更新所有真实已使用模型的 `ASSET_CREDITS.md`（作者/链接/许可/改动/实际路径）；补充 README 引用。
3. 提供清晰的前后对照截图及短视频或动图（若工具允许）。
4. 运行原有全部 QA 与新增场景检查，记录性能对比、失败项和未完成项。
5. 提交可运行代码，而不是只创建方案文件或概念图。
