## 0. 当前仓库基线（开发前必须复核）

根据 2026-11-05 仓库文档与已读取代码：

- 工程：Godot 4.x / GDScript；`CRT_CRAB_Code/crt_crab_devkit/`；Windows `PLAY.cmd` 启动。
- 正式可玩屏幕只有 **BOOT 启动区与 ARCHIVE 档案区**；另外十台屏幕目前为待机、连接或故障展示，不能称为可玩十关。
- 外部场景：三层、12 台、360° 复古 CRT 电脑堆叠；屏幕内部是 **320×240 的侧视 2D 像素解谜**。
- 玩家螃蟹**绝不离开屏幕画面**，不爬电脑外壳、键盘或实体底座；三维电脑塔用于陈列、观察和跨屏镜头过渡。
- 现有玩法：跑跳、梯子、钳击、推拉、压力板、滚石、宝箱、晶体、数据虫、两关往返、跨屏持续信号、检查点及存档。
- 两关数据共可获取 **17 晶体（未消费、全部收集时）**：BOOT 地图拾取 3 + 宝箱 2/4；ARCHIVE 地图拾取 1 + 宝箱 3/4。晶体目前仅有 **1 晶体恢复 1 生命** 的实际消费用途，回血上限 3 心。
- `scripts/main.gd` 启动后直接加载存档中的关卡并运行 `_intro()` 约 2.8 秒镜头，没有真正的标题菜单。
- `scripts/shell_director.gd` 已提供 3D 跨设备镜头运动，普通时长约 1.35 秒；`scripts/main.gd::_travel()` 已有 `interference` 参数与 `travel` 音效，但没有**螃蟹在旧屏幕像素分解、目标屏幕像素重组**的完整角色传送动画。
- `scripts/save_store.gd` 使用 `user://progress.json`，现为 v2；`scripts/hud.gd` 负责现有 HUD / 暂停界面；`scripts/side_world.gd` 负责晶体、宝箱与回血终端。

**以上是项目状态核对基线，不得盲目覆盖；正式动工前重新审查仓库最新提交。** 先创建回退分支/提交，记录现有测试通过情况；如实现已更新，则先对比差异再开发。

## 1. 不可改变的项目规则

1. 保留**三层、12 台、360° 的 CRT 电脑阵列**，不改成一排显示器、普通房间或单面电脑墙。
2. 保留已完成的 BOOT / ARCHIVE 两屏解谜、箱石物理、宝箱唯一领取、跨屏信号、相机与存档功能。
3. 2D 螃蟹在屏幕内部活动；所有传送粒子、角色溶解和重组均发生在**数字画面内部**，绝无实体螃蟹跑到屏幕外。
4. 仅在界面/UI里选择外观；外观不改变物理碰撞、攻击范围、跳跃、移动速度和机关重量。
5. 补充视觉与交互，不使用廉价 Flash 平面风、满屏粒子、发灰模糊水彩、大面积浮夸 Bloom。主要视觉方向为**Y2K 复古消费电子 + 潮酷街头平面设计 + 低模机壳与清晰像素画面**。
6. 参考《钻石狂潮》是机制灵感，**不能复制原作关卡布局、贴图、音乐、人物或商标**。
7. 不凭空声称 Sketchfab 第三方模型已下载导入。本轮需求与外围素材工作相互兼容，但独立验收。

## 2. 主菜单与正式启动流程（P0）

### 2.1 游戏启动后的第一屏

- 显示 **3D 电脑塔实景**：镜头从经过设计的固定机位缓慢环绕/轻推镜（待机相机），已完成区域显示低频画面，其他 CRT 显示各自待机/锁定状态。
- 左侧或前景一侧放标题 `CRT 小蟹闯塔记`，英文副标 `CRT CRAB // SCREEN ADVENTURE`，伴随原创电子启动提示。
- 有明显可读的主要按钮，不用把 UI 贴在不容易点击的 3D 屏幕上；保证标题、菜单与电脑塔主体不相互遮挡。
- 配色：#151923 / #DDD4C2 / #DCE65B / #EA5985 / #54CFC3。排版原创街头贴标感，标题大小醒目、按钮清晰、动态克制。
- **首次启动不得自动进入 BOOT 关卡**；在玩家确认按钮前处于 `MAIN_MENU`，角色控制与物理关卡输入锁定。

### 2.2 菜单项和行为

| 按钮 | 行为与条件 | 备注 |
|---|---|---|
| 开始游戏 | 无有效存档时从 BOOT 安全入口开始 | 新存档不应在用户尚未点击时被覆盖 |
| 继续冒险 | 有有效存档时，从上次保存屏幕及安全位置接续 | 启动前先验证存档结构及目标关卡 |
| 新游戏 | 有存档时可见，提示“将覆盖当前游戏进度”二次确认 | 允许取消；建议先备份旧档，完成确认后才重置 |
| 更换服装 | 打开衣橱 UI，可预览、购买、装备造型 | **无需先进入游戏**就可查看已持有皮肤 |
| 游戏设置 | 音乐/音效、减少动态、画面模式、音量 | 优先复用现有设置逻辑，新增设置需持久化 |
| 退出游戏 | 保存必要设置后正常退出 | Windows 版有效，不让按钮成为无响应装饰 |

建议视觉文本：`PRESS START`、`SYSTEM ONLINE`、`SIGNAL FOUND`、`OUTFIT DATA`，均为游戏自有文本。

### 2.3 细节交互

- 鼠标点击 + 键盘上下选择/Enter 确认/Esc 返回；按钮 hover/focus/pressed 要有声音或轻量反馈。
- 进入换装/设置后，退回主菜单时要保留当前菜单焦点、音频状态。
- 从暂停菜单新增 `返回主菜单`；应先保存，再退出可玩场景，回到 `MAIN_MENU`，**不是直接退出进程**。
- 退出/重进后菜单正常显示，不应绕过菜单自动复玩。
- **减少动态**开启时，主菜单待机镜头可以静止或仅极轻微移动。
- 菜单在 1280×800 和窄/竖窗口（至少 720×900）均须可读；避免标题与按钮溢出或挡住主体 CRT。

### 2.4 输入/场景状态机

新增或扩展状态：

```text
BOOTSTRAP → MAIN_MENU ↔ WARDROBE / SETTINGS
                 ↓ 开始 / 继续
               PLAY_2D ↔ ARRAY_VIEW
                 ↕
              PAUSED → MAIN_MENU
                 ↓ 端口
  TRANSITION_EXIT_2D → TRANSITION_3D → TRANSITION_ENTER_2D → PLAY_2D
```

规则：任何**菜单中**、**换装中**和**转场中**的输入都不能泄漏给 2D 游戏；QA/性能模式可按已有测试设计跳过标题菜单，但正式玩家启动不跳过。

## 3. 螃蟹更换服装与衣橱系统（P0）

### 3.1 设计目标

- 衣橱作为晶体货币的首个持续消费场景。
- 每套外观可在菜单内看到**实际像素螃蟹**的待机、走动与钳击帧，不接受仅放一张无关概念图作“服装预览”。
- 切换的是颜色、饰品与局部像素层；尽量不改变轮廓辨识度、小蟹尺寸和碰撞盒。

### 3.2 第一阶段 4 个条目（默认 1 + 可付费 2 + 隐藏 1）

| ID | 显示名 | 解锁方式 | 视觉特征 |
|---|---|---|---|
| `classic_orange` | 默认小橘蟹 | 默认拥有 | 橘色蟹壳、基础小钳子；参考当前主角的辨识造型 |
| `silver_shell` | 银壳蟹 | 6 晶体 | 银灰蟹壳、黑色小墨镜，金属边缘点光 |
| `cyber_crab` | 赛博蟹 | 8 晶体 | 暗紫/薄荷青分色、科技小耳机/发光小部件 |
| `glitch_crab` | 故障蟹 | ARCHIVE 隐藏宝箱首次获取后解锁 | 黑梅紫壳、少量像素错位特征；不长期闪烁伤眼 |

建议的 **6 + 8** 定价以当前两关**最多可得 17 晶体**为依据，允许正常游玩解锁两套付费外观并留余量。数值应放配置表，不要写死在 UI 代码里。

> 重要：不要因为“购买两套服装”成为硬性任务而让玩家陷入晶体不够。服装是可选的；金币不够时明确显示价格和当前余额。故障蟹与隐藏宝箱解锁绑定，**不是再付费**。

### 3.3 衣橱页面与交互

- 左/中：大尺寸像素角色预览（最近邻，保证像素清晰）；待机/走动/钳击切换、可暂停预览。
- 右：服装卡片（名称、价格、持有状态、当前装备）。
- 未持有：显示晶体价格、`解锁`；持有：显示 `装备`；已装备：显示 `已装备`。
- 购买前弹出确认；购买成功扣晶体、添加 ownership，装备行为与购买行为分开。
- 选择一个尚未解锁的隐藏服装时，只显示合理提示：`隐藏数据尚未找到`，不要提前剧透所在精确坐标。
- UI 预览和游戏实体必须调用相同的 sprite/皮肤资产配置，**不允许预览成功而游戏里没变化**。

### 3.4 建议数据结构

在现有 SaveStore v2 数据上**向后兼容增加字段**，推荐迁移到 v3，或为 v2 扩展默认值并测试旧档；两种方式择一并说明。建议：

```json
{
  "version": 3,
  "crystals": 8,
  "wardrobe": {
    "owned": ["classic_orange", "silver_shell"],
    "equipped": "silver_shell"
  },
  "settings": {"music_volume": 0.55, "sfx_volume": 0.8, "reduced_motion": false}
}
```

样例是结构示意，不代表真实存档数值。要保证：旧存档迁移时保留晶体、宝箱、屏幕、机关、生命；没有衣橱字段则补默认造型；无效皮肤 ID 自动回退到默认，不丢失原始存档。

### 3.5 美术实现规则

- 可使用基础身体 sprite + 颜色调色板 + 饰品图层（但动作帧必须对齐）；避免给每套衣服复制整套移动逻辑。
- 保证 320×240 屏幕内看得清；小尺寸角色饰品不能堆满噪点。
- 螃蟹受击、死亡、钳击、跳跃、推拉与复活状态都要正确显示装备外观。
- 非人形的螃蟹不应被强行设计成人形换装角色；重点是“蟹壳、眼镜、耳机、花纹、小配件”。

## 4. 晶体经济：现在除了回血，还能做什么？（P0 + P1）

### 4.1 第一轮必须交付

- 保持原有 `1 晶体回血 1 心`；最多 3 心，满血不扣费。
- 增加**衣橱消费**：银壳 6、赛博 8；玩家通过关卡晶体/宝箱获得货币。
- 购买时使用**原子事务**：验证余额与未持有 → 扣款并授予 → 同步保存 → 显示成功；处理磁盘写入失败时不能“扣了币却没衣服”。
- 宝箱、地图晶体的唯一领取不可因切屏、死亡、R 复位、重启重复领取。
- 服装购买后**不是一次性消耗物品**；拥有状态永久存档。

### 4.2 未来版本可选，不在本轮假装完成

| 用途 | 建议费用 | 条件与限制 |
|---|---:|---|
| 谜题提示（非直接解） | 2 晶体 | 免费第一层观察提示，付费再给操作方向；不可自动开门 |
| 电脑屏幕主题/边框外观 | 6–10 晶体 | 只改变色彩和装饰，不改变实际机关显示清晰度 |
| 唱片/电台曲目解锁 | 4–8 晶体 | 把原创游戏音乐做成可收集装饰，不强制购买 |

**不推荐**晶体购买必需钥匙、主线能力、解除主线机关、直接通关或解锁必须经过的出口。玩家把晶体花在外观上也必须能正常走通主线。

### 4.3 经济显示与平衡验证

- 主菜单/衣橱/游戏 HUD 的余额来自同一数据源。
- 衣橱显示本关已发现的宝箱数、当前可用晶体即可，不要过度剧透。
- 验证 0 晶体、恰好 6、恰好 8、已拥有后重复点击、正在保存时双击、重启后的购买状态。
- 将价格、货币 ID、解锁条件放到单独配置文件（如 `data/cosmetics.json`），便于之后扩关平衡。

## 5. CRT 跨屏传送：由功能转为有辨识度的演出（P0）

### 5.1 用户当前问题

已有关卡切换与 3D 相机沿塔转向目标屏幕，也有简单干扰效果；但玩家没有看见螃蟹在 A 屏幕里消散、在 B 屏幕里重新组成，因而缺少“正在跨屏传输”的观感。要在**保留现有 `ShellDirector.travel()` 和路由**的前提下补演出，而不是重写传送逻辑。

### 5.2 标准版三段流程（总时长建议 1.4–2.0s，试玩可调）

**第一段｜EXIT：旧屏幕内像素分解（0.20–0.35s）**

1. E 触发有效端口，立即锁定操控/受击/多次传送输入。
2. 2D 螃蟹短暂朝端口转向，像素从身体轮廓向连接点方向收束，形成青绿+梅紫的离散块。
3. 主角逻辑位置暂存，视觉层消失，屏幕出现短暂局部扫描线/信号波纹。
4. 播放轻短的电子语音或碎片音（可选 `CONNECTING...`）。

**第二段｜LINK：电脑塔 3D 传输（沿用并增强，约 0.8–1.2s）**

1. 3D 相机从 A CRT 略后撤/平移/环绕，连续转向目标 B CRT；尽量不穿过机壳。
2. 已知的 A→B 数据连线可出现一段**沿线跑动的信号亮点**，幅度克制，不做全场爆闪。
3. 旧屏幕冻结上一帧或显示明确离线状态，不让两块 CRT 同时显示两只可玩的螃蟹。
4. 在安全节点预载 B 关卡、验证出生点；若加载失败回滚到 A，绝不能卡黑屏或失去控制。

**第三段｜ENTER：目标屏幕内像素重组（0.25–0.40s）**

1. B 屏幕预设出生点处出现青绿色方块，迅速聚合为**当前所穿服装的螃蟹**。
2. 地面释放一圈非常轻微的数字涟漪 + 小段 `LINK ESTABLISHED` 合成音。
3. 恢复操作，2D Camera2D 跟随螃蟹；玩家能立刻看清周围机关。
4. 只在画面内表现数据传输；绝不让蟹飞出 CRT 外壳。

**要求：** 2D 角色的像素碎片贴合角色 sprite，而不是整个屏幕爆炸式粒子。可以用 shader + sprite 蒙版、像素块采样或受控粒子对象池实现。优先清晰且稳定，效果需适配全部皮肤。

### 5.3 减少动态及无障碍处理

- “减少转场动态”启用时：**保留清楚的去向反馈**，取消高速环绕、快速闪屏、大量颗粒；推荐 0.1s 轻淡入/淡出 + 屏幕名称文字 + 稳定 3D 短切。
- 不做全屏强频闪、不做强色差/高强度摇晃、不用大面积 Bloom 隐藏画面。
- 传送失败统一反馈 `NO SIGNAL / 连接失败，已返回原屏幕`；保证控制/状态恢复。

### 5.4 声音方向

- 补 `start / select / purchase / error / transfer_exit / transfer_link / transfer_enter` 轻量电子音效。
- 可选的机器人音色应是**非真人、非真实女声**，参考轻巧合成语音，而不是让人声唱整句旋律。
- 台词建议极短：`Connecting...` → `Link established!`；失败 `No signal!`。
- 不强制依赖 Suno 音乐文件启动游戏；没有音频资源时音效系统也不能抛错。

### 5.5 状态切换安全规则

- 只能从一个有效的 portal 发起一次转场；转场 token 防止重复 E。
- A 的保存先于加载 B；B 的出生点必须有效且无遮挡。
- 目标加载失败回滚后，A 的画面、螃蟹、HUD、输入全部恢复。
- 传送期间不允许后台的敌人继续造成伤害；不允许购买/暂停/重置热键破坏中途状态。
- 跨屏信号和已开宝箱、已装备服装均不因转场丢失。

## 6. 灵感说明与仓库文档（P0）

### 6.1 现状

玩法开发书 `CRT_CRAB_Code_B/02_CRT_CRAB_游戏玩法开发书_v1.0.md` 已注明：玩法受到 **Gameloft《钻石狂潮 / Diamond Rush》** 的环境解谜、隐藏收集和机关链条启发，采用原创关卡与素材。

但**仓库首页 README 目前未醒目标明解谜玩法灵感**；建议补一小节“玩法灵感与原创特色”。

### 6.2 可直接写入 README 的文字

> **玩法灵感**  
> 本作的侧视像素机关解谜，受到 Gameloft 经典手机游戏《Diamond Rush（钻石狂潮）》的启发：可推动物体、落石、压力机关、隐藏道路与宝箱探索。CRT 小蟹闯塔记采用原创角色、关卡布局与图形资源，并将谜题拓展为**不同复古电脑屏幕之间的持续信号联动**。玩家始终在 CRT 的 2D 屏幕世界中冒险，3D 电脑塔提供彼此连接的空间舞台。此处为灵感致谢，不代表与原作开发商存在合作或授权关系。

### 7.1 兼容性重点

- **不要重写**已有 `SaveStore` 的整份保存数据；兼容迁移、字段白名单与回退备份。
- 如果要使用独立场景 UI，可把菜单实现为 CanvasLayer 或 Control 场景，不要把所有控件、配色和信号全塞进 `main.gd`。
- 背景计算/3D 塔依旧只生成一次；从暂停“返回菜单”不应重复实例化 12 台 CRT、引起内存暴涨。
- 衣橱只是角色的**视觉映射**，从玩家 sprite atlas 切换，不创建额外角色实体。
- 进游戏后 UI 隐藏才允许关卡输入；从游戏回主菜单后设置、存档和选中衣服都继续有效。

## 9. 必须执行的回归测试清单

1. **旧档兼容**：原 v2 存档进入菜单并可继续 BOOT/ARCHIVE；原晶体/宝箱/重石位置、信号、生命不丢失。
2. **首次启动**：无档显示开始游戏，点击后 BOOT 正常；重启返回菜单。
3. **新游戏**：确认前不能覆盖旧存档；取消无数据变化；确认后从 BOOT 进入。
4. **余额与消费**：0、5、6、8、14、17 晶体；不足额、足额、双击、已购买重复解锁、异常存盘。
5. **装备持久化**：菜单装备 → 入关 → 走跳钳击受伤推拉 → 切屏 → 重启 → 仍是相同外观。
6. **隐藏款**：ARCHIVE 隐藏宝箱首次领取才解锁；R 复位/重新进关卡不反复发奖。
7. **转场状态**：从 BOOT→ARCHIVE、ARCHIVE→BOOT；两方向都有 EXIT / LINK / ENTER，减少动态模式也正常。
8. **异常路由**：无效目标、丢失出生点、转场中连续按 E、关卡预载失败均能回到安全状态。
9. **控制隔离**：菜单/换装/转场按 J、E、R、Tab 不会误伤、开箱或重置谜题。
10. **画面与性能**：1280×800、720×900 下 UI 不溢出；2D 最近邻清晰；12 台 CRT、原有美术及输入响应无退化。
11. **正式存档安全**：自动化 QA 用独立临时路径；不能读取、改写或删除用户正式 `user://progress.json`。
12. **交付证据**：实际游戏窗口截图及连贯转场画面来自真实运行，不得使用概念图、静态 UI 设计稿冒充完工。
