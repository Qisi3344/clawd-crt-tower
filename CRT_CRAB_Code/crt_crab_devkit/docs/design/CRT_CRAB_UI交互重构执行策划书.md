# 《CRT小蟹闯塔记 / CRT CRAB》UI 与交互重构执行策划书

> **用途**：直接交给 Codex，在现有 `Qisi3344/clawd-crt-tower` 仓库中实施。  
> **版本**：UI-01 · 2026-11-08  
> **优先级**：先修 HUD 和操作引导，再做阵列、暂停和剧情美术精修；不要一次性推翻全部界面。  
> **依据**：当前讨论中的 UI 反馈、《关于UI.txt》以及已核对的 GitHub `main` 分支源码。实施前必须重新读取仓库最新状态，不可假设以下代码路径和实现从此不再变化。

---

## 0. 一句话目标

**让玩家把注意力放在 CRT 屏幕里的小螃蟹、关卡与机关上，而不是阅读常驻说明和程序员式面板。**

保留“3D 复古电脑塔 + 320×240 的 2D 像素游戏”的双层世界。界面风格是**精致的复古电子娱乐设备 / 90 年代即时通讯 / 潮流游戏 UI**，而不是调试器、命令行终端，亦不是普通手机 App 的扁平化皮肤。

本次目标分四部分：

1. **减法**：游戏中仅常驻最必要的信息，操作说明变成首次教学与按需提示。
2. **结构**：主菜单、暂停菜单、操作指南、阵列观察、剧情消息各有清晰层级。
3. **双输入**：开始游戏时选择“键鼠 / 触屏”，游戏内可随时更改；不开发手柄支持的新 UI。
4. **落地**：实际修改 Godot 项目、运行测试、交付真实截图与问题记录，不允许只写方案或只提供概念图。

### 1.1 已核对的项目情况

| 维度 | 项目当前情况 |
|---|---|
| 仓库 | `https://github.com/Qisi3344/clawd-crt-tower` |
| 工程位置 | `CRT_CRAB_Code/crt_crab_devkit/` |
| 引擎与脚本 | Godot 4.x / GDScript（现有文档建议 4.7.2） |
| 3D 部分 | 12 台立体 CRT 设备、阵列镜头、外围游戏厅 |
| 2D 部分 | 单个活动 SubViewport，320×240、4:3 像素关卡 |
| 当前进度 | 仓库文档称六屏主线首版可通关；玩法、美术与输入适配仍在迭代 |
| 输入情况 | 键鼠已存在；实体手机触控与平台导出在已阅文档中明确为未完成 |

### 1.2 绝对红线

- **不得重建项目、迁移引擎或推倒现有主场景**；原有 3D 电脑塔、各屏幕内容及双世界结构保持。
- **不改游戏机制**：走、跳、攀梯、推拉、螯击、复位、传送、Boss、关卡触发与机关判定不因为 UI 变更而改变。
- **不破坏存档**：原 `user://progress.json`、外观和扭蛋收藏照常加载；设置和教程进度建议单独保存。
- **不取消真正的交互反馈**：靠近机关时“E 交互”等提示可以按需出现；禁止为了干净而让玩家找不到操作入口。
- **不做独立网页覆盖 Godot**：游戏本体 UI 用 Godot 原生 Control/CanvasLayer/Theme 等实现。
- **不把所有字体一刀切变成大号像素字**；更不使用大面积等宽调试器布局。
- **手机虚拟操作不是装饰图**：多点触控、持续按住、左右移动与动作同时进行必须实际有效。
- **本阶段不新增手柄选择、手柄图标或手柄专属教学**。保留已有映射即可，不主动移除旧兼容性。

## 3. 信息架构：主菜单与游戏内

### 3.1 主菜单（不添加过多顶级按钮）

```text
CRT小蟹闯塔记

[继续冒险]   （无存档时隐藏）
[开始游戏]   （已有存档时为“新游戏”，保留确认）
[宠物扭蛋]
[更换服装]
[设置]
[退出]
```

设置页内部划分为：**游戏 / 操作 / 音频 / 画面**，也可做一个分段页签，避免无限向下滚动。操作页包含“操作方式”“操作指南”“教学提示”三项。

### 3.2 开始游戏后，首次选择操作方式

```text
选择操作方式

[⌨ 键鼠操作]     [◉ 触屏操作]

可随时在“设置 → 操作方式”中更改。
                  [确认进入]
```

**规则**：

- 第一次开始游戏且尚无保存的操作方式时弹出；已有选择时直接进入，避免每次读档重复打断。
- “继续冒险”如没有保存的方式也需选择一次；“新游戏”不需要强迫重新选择，设置里随时改。
- 可以根据设备是否支持触屏**猜测默认高亮**，但不得自动跳过玩家确认。判定不可靠时默认键鼠。
- 选项只有**键鼠、触屏**，不显示手柄；可以在电脑上手动选触屏，用于虚拟按键测试。
- 选择写入独立偏好配置，例如 `user://controls.cfg`；不要覆盖冒险进度。
- 输入方式切换不要求重新启动、不传送角色、不重置关卡；如果当前处于剧情、过屏转场或暂停，等安全的 UI 状态完成切换。

## 4. 普通闯关 HUD：保留什么、删掉什么

### 4.1 永久常驻，仅保留 4 组

1. **左上**：单行关卡标识，如 `04 · 回收站`；标题在进入时可短暂展开为完整章节名，约 2～3 秒后收起。
2. **左上第二行（紧凑）**：晶体、宝箱计数、修复屏幕数的清晰小图标 + 数字；过小空间可先保留晶体及当前任务最相关的一个计数，其余放暂停页。
3. **右上**：3 格可辨认的生命图形（建议小螃蟹爪/心形，不再只是无解释圆点），阵列按钮，暂停按钮。
4. **场景正下方附近**：仅当靠近可交互对象时显示的上下文提示，例如 `E · 打开宝箱`、`按住 E + 方向 · 推拉`。无可交互对象时完全隐藏。

### 4.2 从常驻 HUD 移除

- 底部全量按键列表：`AD 移动 / 空格跳 / W/S 梯子 / E 推拉 / J 螯击 / R 复位`。
- 左上长句型目标说明，例如“启动密钥已记录 · 向右连接 ARCHIVE”。
- 长时间显示的调试说明、英文状态标语、泛用操作说明。
- 没有语义的全局游戏名大横幅（可放主菜单或短暂的关卡入场条）。

### 4.3 信息出现的触发规则

| 信息 | 何时出现 | 何时消失 |
|---|---|---|
| 章节名 | 首次进章节或切屏成功 | 2～3 秒后收为一行 |
| 短目标反馈 | 获得密钥、打开门、线路连接等进度变化 | 3～5 秒后淡出；暂停页可查看完整当前目标 |
| 机关操作 | 进入机关有效交互范围且可以操作 | 离开范围/完成操作即消失 |
| 新机制教程 | 首次遭遇、当前输入方式下未学过 | 玩家完成对应操作后消失；学习状态持久记录 |
| 获得物品 | 拾取晶体、宝箱或新道具 | 2～4 秒后淡出 |
| 生命变化 | 持续可见，受伤时轻微强调 | 强调效果短暂结束，生命常驻 |
| 错误/失败 | 当前操作失败、传送失败等 | 阅读时间足够；重要错误可手动关闭或重复查看 |

**冲突规则**：重要错误 ＞ 当前机关提示 ＞ 教程引导 ＞ 普通拾取通知。不可同屏叠三条字；高优先级到来时低优先级排队或合并，不丢关键反馈。

## 5. 操作教学：玩家做对一次，提示才完成

原则：**教学嵌在真实关卡里，不开新测试场景、不长篇弹窗、不冻结玩家看说明。** 普通提示几秒后可消失，但“新操作学习完成”应以实际动作事件为准，而不是到时就算学会。

| 次序 | 触发条件 | 键鼠文案示例 | 触屏文案示例 | 完成条件 |
|---|---|---|---|---|
| 1 移动 | 第一次进入可操作 BOOT | `A / D · 移动` | `拖动左侧摇杆 · 移动` | 玩家实际移动达到短距离 |
| 2 跳跃 | 靠近第一个安全小沟/跳跃位置 | `空格 · 跳跃` | `点击跳跃键` | 发生一次有效跳跃并落地 |
| 3 推拉 | 首次接近可推动箱石 | `按住 E + A/D · 推拉` | `按住交互键 + 左摇杆` | 箱石移动一格或成功推入目标 |
| 4 攀梯 | 首次靠近梯子 | `W / S · 攀爬` | `摇杆向上/下 · 攀爬` | 实际攀爬一小段 |
| 5 宝箱/机关 | 首次进入宝箱或终端范围 | `E · 互动` | `点击交互键` | 成功交互 |
| 6 螯击 | 首次接近可攻击目标 | `J · 螯击` | `点击攻击键` | 成功进行一次攻击；必要时要求命中 |
| 7 复位 | 首次陷入箱石谜题或主动打开指南 | `R · 复位当前谜题` | `暂停 → 复位谜题` | 玩家主动复位或明确查看说明 |
| 8 阵列 | 第一次开放阵列观察 | `Tab · 查看电脑阵列` | `点击阵列图标` | 打开一次阵列模式 |

后续 RECYCLE / SIGNAL / ERROR 等特殊机制：**第一次遇到新的机制时才说明，不要预先讲完所有能力**。可由各机关发出稳定的教程事件 ID，不建议用字符串匹配提示内容判断是否学过。

- 每个教学有唯一标识，例如 `move`, `jump`, `push_pull`, `ladder`, `attack`, `array_view`, `magnet`, `conveyor_reverse`。
- 同一操作方式、同一教学默认只播放一次；切换键鼠/触屏后，已知的概念可以保留，但新的输入方式需要显示相应操作提示。
- 玩家完成实际动作才标记 `completed`；若玩家早已熟练完成动作，可以直接标记，无需强制等待动画。
- 长时间卡住时最多增加一次轻量提示（例如连续 25～35 秒附近、未暂停且没有主动操作成功），不得一直闪烁、重复弹出。
- 设置提供 `教学提示：开启 / 关闭`；关闭后不主动弹教程，但仍保留近场交互提示及操作指南。
- 教学状态独立于 `progress.json`，或经明确版本迁移后安全存储；不清空旧宝箱、能力和存档。

## 6. 操作指南：主菜单、暂停菜单同一套数据

### 6.1 入口

- 主菜单：`设置 → 操作 → 操作指南`。
- 暂停界面：直接显示 `操作指南` 按钮，进入后能返回暂停页，焦点位置保留。
- 当前显示对应操作方式的说明，不同时展示全部键鼠和触屏按键；操作指南顶部可临时切换查看另一方式，但不改变实际输入模式，除非用户明确点击“应用此模式”。

### 6.2 内容分组

| 分组 | 键鼠 | 触屏 |
|---|---|---|
| 移动 | A/D、左右方向键 | 左侧虚拟摇杆 |
| 跳跃 | 空格 | 跳跃键 |
| 梯子 | W/S、上下方向键 | 靠近梯子后摇杆上/下 |
| 攻击 | J、鼠标左键 | 攻击键 |
| 交互 | E/K | 交互键 |
| 推拉 | 按住 E/K + 方向 | 按住交互键 + 摇杆 |
| 复位 | R | 暂停菜单 → 复位谜题 |
| 阵列 | Tab，拖动环绕、滚轮高度 | 阵列按钮，拖动旋转、触摸缩放/高度调节（实现并测试后再显示准确手势说明） |
| 暂停 | Esc | 暂停按钮 |

注意：Godot 现有 README 也列了部分手柄映射，但**本阶段操作指南不展示手柄页面**。任何尚未实装的触屏手势不得提前写成已支持。

## 7. 触屏版布局（移动端必须横屏优先）

### 7.1 布局

```text
┌─────────────────────────────────────────────────────┐
│ 04·回收站  ◆19  ▣7/9            ♥♥♥   [阵列] [暂停] │
│                                                     │
│                CRT / 活动像素关卡                   │
│                                                     │
│  [虚拟摇杆]                        [J螯击] [跳跃]  │
│                                     [E交互/推拉]   │
└─────────────────────────────────────────────────────┘
```

- 左下：**圆形模拟摇杆**，可连续水平移动，靠近梯子时支持上/下。不是“一点走一格”的四个方块按钮。
- 右下：**跳跃、螯击、交互/推拉** 三个圆形触控键，排列要给双指同时按压留出空间。
- 右上：阵列与暂停；复位放到暂停菜单，避免误触破坏谜题。
- 控件半透明、边缘清晰，有按下反馈，整体贴屏幕左右两侧、留安全边距；不能压住主角、关卡目标和关键机关。
- 虚拟按钮启用时，键鼠版底部不出现任何虚拟键；切换模式即时更新。

### 7.2 可用性标准

- 真实支持多点触控：左手推摇杆同时右手按跳跃/攻击/持续按交互；不能把长按误认为短按。
- 触屏 UI 在拖动阵列视角时不应与角色摇杆冲突；阵列模式隐藏玩法按钮，只保留阵列相关操作。
- 设备横竖比例变化时不能消失、越界或被 CRT 边框遮挡；手机版优先横屏，竖屏只做引导横屏或适配容错，不要强行把主玩法压成一条窄缝。
- 触屏按钮不依赖悬停（hover）；点击区域建议不小于约 44×44 逻辑像素，重要动作区域应更大，并在真机实测。
- 当前仓库尚未正式实现移动端触控/导出，**不能用 PC 竖窗口截图声称已完成手机适配**。首轮可先在桌面模拟触控，随后必须 Android/iOS 或实际目标平台验证。

### 7.3 3D 镜头和屏幕可读性

- **游戏主角仍然只在 2D CRT 内**，不为了适配手机把它移到电脑底座。
- 当活动屏幕聚焦时，保证内屏相对可视区域足够大；必要时调整相机 framing，而不是放大 320×240 的原始画布分辨率。
- 任何 HUD 或虚拟摇杆不得抢走玩家对 CRT 像素画面的视线；对小屏优先隐藏次要统计信息。
- 过屏动画仍由原 `ShellDirector` 和传送系统控制，屏幕边缘与外部电脑可被镜头展示，但不让操作控件遮挡转场主角。

## 8. 电脑阵列（Tab）重新设计

目标：让玩家一眼看出**自己在哪台 CRT、哪几台可进入、哪几台已修复、哪里暂时未连接**，而不是读一整页字符串。

### 8.1 版式

- 进入阵列模式后：镜头显示 360° 电脑塔；右侧出现约占屏宽 24%～30% 的信息栏，窄窗口可折叠到顶部/底部。
- 顶部：`电脑阵列` + `当前连接：RECYCLE`。
- 中间：六个主线屏幕各一行（图标、简短中文名、明确状态）。英文代号可以缩成小标签，作为装饰信息，而非唯一可读名称。
- 底部：只保留当前目标相关状态，例如 `ARCHIVE 信号已连接`、`消息仍未送达`。
- 第一次进入短暂提示：键鼠 `拖动旋转 / 滚轮调整高度 / Tab 返回`；触屏仅提示**实际实现的**手势。之后不常驻操作说明。

### 8.2 状态与交互

- **已修复**：明确完成图标；**可进入**：连通图标；**未连接**：锁/断线图标；**当前**：高亮边框。状态不能只靠颜色区分。
- 阵列面板**仅查看，不开放随意点击传送**：原传送关卡端口仍然是实际穿梭入口。
- Tab / 阵列按钮再次操作返回当前屏幕；恢复原输入，不让玩家在阵列观察时继续控制关卡角色。
- 六关全展示时必须自动收纳；不得在 1280×800、720×900 或窄窗里裁切底行和操作说明。

## 10. 剧情开场与结局界面

当前开场里有 `MESSAGES / User ↔ Clawd`、代码窗口、诊断区与 `REPAIR` 字样。故事里“还在吗？→ 发送失败 → Clawd 自己修复连接”是值得保留的核心情绪，**不能改成一个普通手机聊天 App**。

### 10.1 推荐视觉结构

- **主视区（约 60%～70%）**：复古桌面聊天窗口，像 1990s/2000s IM，显示 User 与 Clawd 的消息；不必保留大片等宽全大写标题。
- **次视区（约 30%～40%）**：可折叠的代码/连接状态窗，正常时低对比；异常时局部突出 `NO SIGNAL`。
- **小螃蟹**：在聊天窗口边沿留专属位置，不要踩在密集代码行上；动作随剧情移动。
- **状态反馈**：消息发送失败、重连、最终送达要形成视觉层次，避免用大块红/黄警报占满画面。
- **按钮**：真正可点的只有“跳过剧情”等实际交互项；其余舞台文字不要伪装成可点击控件。

### 10.2 `REPAIR` 的交互定义（本次默认）

当前代码中 `REPAIR` 是 Label，且剧情时间线为自动演出。**本次默认保留自动修复演出**：让“REPAIR”表现为螃蟹正在操作的屏幕内系统控件，而不是要求玩家点击它才能继续。若以后要做手动点击修复小游戏，另立需求，不要悄悄改写剧情推进逻辑。

保持：自然播放、Esc/跳过、失焦暂停、回看/继续逻辑以及消息送达后的结局状态。布局要在横向和较窄窗口下重排，不许文字互相遮挡。

## 11. 美术规范：统一，但不机械复制

### 11.1 配色

延续现有 `retro_ui.gd` 已使用的主色关系，做“低饱和紫黑底 + 粉紫/电子青小面积强调”：

| 作用 | 建议色 |
|---|---|
| 深色背景 | `#17121F` |
| 常规面板 | `#292033` |
| 次层面板 | `#41334D` |
| 轮廓与分割 | `#68516D` |
| 主文字 | `#F4E7CF`（可微调偏冷白，避免暖黄旧纸感） |
| 粉色提示 | `#E89AAA` |
| 成功/连接 | `#8DCABB` |
| 次级电子标识 | `#62B8C1` |

配色是**参考色值**，实施时优先复用项目已有主题和实际颜色，不要全场刷成一片粉，也不要用高亮霓虹替代视觉层级。

### 11.2 字体、边框、排版

- 2D 关卡内部继续保留原生像素图与像素字；**屏幕外部的菜单文字要优先保证中文可读性**。
- 标题/关卡标识、正文说明、数字信息、按钮文字分开定字号和字重；不得在 `retro_ui.gd` 将所有 Label/Button 统一到 24/36 像素。
- 适当使用像素切角、细描边、局部发光和 CRT 元素；避免所有界面都变成大黑框 + 密集字表。
- 支持常见小窗口缩放、文本换行、滚动容器和焦点导航；检查中文标点换行。
- 按钮具有正常/按下/不可用/键盘焦点状态；重要状态还要有图标/文案，不能只靠颜色。

## 12. 建议代码拆分（按实际项目结构调整）

不要在 `main.gd` 和 `hud.gd` 里继续追加几百行分支。可采用下列职责拆分，但**不要求为了满足文件名重构全部代码**：

| 职责 | 建议模块 | 核心责任 |
|---|---|---|
| 操作偏好 | `scripts/ui/control_preferences.gd` | 保存键鼠/触屏、教程开关、模式切换；不碰进度存档 |
| 教学管理 | `scripts/ui/tutorial_director.gd` | 接收真实事件、判定首次、显示/完成/重试、教学持久化 |
| 上下文提示 | `scripts/ui/context_prompt.gd`（或 HUD 内子组件） | 消息队列、优先级、显示时长、取消时机 |
| 触控操作 | `scripts/ui/touch_controls.gd` | 虚拟摇杆、动作键、长按、多指、输入映射与安全区 |
| 操作指南 | `scripts/ui/controls_guide.gd` | 按当前模式渲染统一按键映射，主菜单和暂停复用 |
| 阵列面板 | `scripts/ui/overview_panel.gd` | 六关状态列表、折叠布局、返回操作 |
| 样式参数 | Theme / 轻量 UI tokens | 字体层级、色板、间距、圆角或像素切角，不全局硬改 |

设计注意：

- 教学完成事件应从**实际成功操作**发出，而不是通过“检测到玩家按过一次键”推测。例如推拉要在箱石真正移动之后才完成。
- `SideWorld.prompt_changed`、`SideWorld.message`、现有收集更新与 `WorldProgress` 可作为状态来源；避免新 UI 复制旧游戏规则。
- 触屏按钮通过 Godot 输入动作注入，释放时必须成对取消；场景切换、暂停、失焦必须处理“长按卡住”。
- 旧 `InputMode` 已区分 PLAY_2D / TRANSITION_3D / ARRAY_VIEW / PAUSED / MAIN_MENU 等，触屏 UI 可见性必须与现有状态机一致。
- 对应修改自动 QA/截图测试；避免仅根据 GUI 渲染成功来宣称交互正确。
