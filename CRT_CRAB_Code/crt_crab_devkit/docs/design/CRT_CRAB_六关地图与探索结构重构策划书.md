# CRT小蟹闯塔记 / CRT CRAB
## 六关地图与探索结构重构策划书 · Codex 可执行版

**文档类型：** 关卡设计 + Godot 技术改造 + 分阶段验收  
**版本：** v1.0｜2026-11-08  
**适用仓库：** `Qisi3344/clawd-crt-tower`  
**工程目录：** `CRT_CRAB_Code/crt_crab_devkit/`  
**核心原则：** 保留“外部 3D 电脑塔 + 屏幕内部 2D 像素冒险”的双层结构；本轮重点重做 **屏幕内部六关的空间结构、探索导航与镜头**，不推倒现有玩法。

> **一句话目标：** 把“直路上摆几个梯子和机关”的六关，改成各有主题、能够向上向下探索、拥有真实岔路、隐藏区域和回环捷径的六座数字迷宫。要让玩家享受“发现新道路”，而不只是“走得更远”。

---

## 0. 先明确需求：我们不是要什么

玩家已明确指出：现有游玩体验是“进去一通乱走、乱传送，不知道自己在哪儿”，而且地图像“一条直路，直路上放几个梯子”。想要的是 **一条主线路中途会分叉，能往上、往下、往里绕，最终还能重新连回主路**。

- **不要**将现有平台简单横向加长、重复摆箱子与梯子，冒充大地图。
- **不要**把多个小房间用 A→B→C 的传送口串起来，冒充纵深。
- **不要**每个岔路都只能单向走到底再原路返回；至少要有可开启的回环。
- **不要**做成纯粹找不到路的迷宫；玩家可以迷路片刻，但应建立位置认知。
- **不要**添加真正的第三维移动：本轮“纵深”指 **2D 横版地图的上下空间、前后路线选择感与探索层次**，不是把屏幕内游戏改成 2.5D/3D。
- **不要**把操作提示、任务文字长期盖在屏幕上；需与单独的 UI 重构策划兼容。

### 成品体验目标

进入一关 → 看见一个显眼地标和当前小目标 → 在中央区域发现上下分岔 → 选择主线或支线 → 在支线获取线索、关键道具或秘密 → 改变环境/打开捷径 → 从另一个入口返回熟悉的场景 → 明确知道“下一步去哪”，但仍有探索空间。

## 1. 现有仓库审查结论（与新设计严格区分）

以下为 2026-11-08 阅读工程文件后的**代码现状**，不是建议稿中虚构的完成项。

| 项目 | 已有代码 | 当前影响 |
|---|---|---|
| 引擎与玩法 | Godot 4.x / GDScript；外部 3D CRT + 内部单个 320×240 `SubViewport` | 必须保留 320×240 的像素画面输出，不因世界变大而拉高画布分辨率 |
| 地图尺寸 | `scripts/room_catalog.gd` 的 `valid_room()` 限制房间宽度 **320–768**、高度 **240–256** | 目前不具备大型纵向空间的尺寸条件 |
| 镜头 | `scripts/side_world.gd` 的 `_snap_camera()` 使用横向跟随、纵向固定 **Y=120** | 玩家不能在同一大区域内被镜头跟随探索多层高度 |
| 坐标 | `SideWorld.point()` 只接受约 **X≤768、Y≤256** 的坐标 | 仅修改 JSON 地图尺寸，会导致坐标校验失效或出生点回退 |
| 房间结构 | 六关中 BOOT、ARCHIVE 是单张旧地图；后四关使用 `rooms` 与 `room_portals` | 已有房间切换能力，但房间内仍多为横向小区域 |
| RECYCLE 示例 | `sorter(480×240)` → `well(320×240)` → `cache(320×240)`，`well` 另分出 `tunnel(320×240)` | 有树状分叉，但缺少连接回路，实际每间房仍较短 |
| 现有机关 | 推拉、落石、重压板、输送带、磁吸、保险丝、机械动物、三路信号、Boss | 这些都值得保留并迁移；重点改路线组织，而不是重写全部机关 |
| 主线与存档 | 六关、九个宝箱、六段通信修复、v4 存档及回访 | 任何重构都必须保护旧存档和剧情条件 |

**源码入口：** `data/levels/{boot_01,archive_01,popup_01,recycle_01,signal_01,error_01}.json`、`scripts/room_catalog.gd`、`scripts/side_world.gd`、`scripts/main.gd`、`scripts/hud.gd`、`data/screen_links.json`。

## 2. 游戏的两套地图，必须分开

### 2.1 `Tab`：CRT 阵列地图（跨电脑）

目的：告诉玩家 **自己位于哪一台实体 CRT、上一台是哪台、下一台可能去哪**。

- 仍显示 360° 电脑塔；可辅以示意化的六台主线节点关系。
- 当前 CRT 用明确描边或微动标记，已修复、可进入、未连接各有不同状态。
- 标出玩家刚刚经过的 **来源 CRT → 目标 CRT**。
- 不允许点击阵列随意瞬移，跨屏仍依赖真实关卡端口和解锁条件。

### 2.2 `M` / 暂停页：当前关卡地图（电脑内部）

目的：告诉玩家 **位于哪间房、哪一层、哪些路走过、哪条支路待探索**。

- 默认只显示玩家已探索区域的轮廓；未探索区域用雾化或问号，避免剧透。
- 同一关卡的所有房间/区域绘制成统一的空间关系图；房间间已有端口要显示连通关系。
- 当前所在区域明确高亮；主目标只需一个简短标识（不画强制导航轨迹）。
- 只标记已发现的主门、捷径、已找到的宝箱；隐藏房间未发现前不直接暴露。
- 关卡内地图应能与暂停菜单里的“地图”入口共用实现；**不要与 CRT 阵列观察混用**。
- 如果 M 键存在映射冲突，以既有输入路由为准；触屏入口待 UI 阶段统一实现。

### 2.3 传送的认知规则

- **房间内连接**：发生在同一台 CRT 内；保留短淡切或相机连续移动，进入下一房间时短暂出现 `RECYCLE / 磁吸井 · 下层`。
- **跨 CRT 连接**：保留现有像素分解 → 3D 镜头穿梭 → 像素重组，展示 `RECYCLE → SIGNAL`。
- 每个门口附近做稳定的目标标识；双向门两侧沿用相同符号。随机端口不能突然改变目的地。
- 返回原路后应有明确“你回来了”的地标识别，而非所有出口都长一样。

## 3. 地图设计的统一约束

### 3.1 空间拓扑标准（设计目标，不是死板格子数）

每个大关至少具备：

1. **一条易理解的主线**：玩家不看地图也能粗略推进。
2. **2–4 个有用途的分岔**：可分别承担机关、战斗、探索或剧情。
3. **至少 2 个明显高度层级**；中后期建议 3 层或更多局部高差。
4. **至少 1 条真正的回环/捷径**：从 A 经 B、C 后，可经 D 回到 A 附近；不是单向的死胡同传送。
5. **至少 1 处可见却暂时不能进入的区域**：玩家之后获得解法或机关信号再返回。
6. **1 个强地标 + 2 个次地标**：玩家能通过画面而不是只靠 HUD 辨认位置。
7. **奖励分布**：主线目标可达，隐藏收集物位于可选区域；所有关键解法都有可观察线索。

**不要求每个房间都复杂。** 安全区、剧情区可以短；主探索区必须有实际分层与连接。关卡大不等于所有道路必须很长。

### 3.2 路线设计要避免的“假分叉”

**不合格：** `入口 → 走廊 → 梯子 → 走廊 → 传送门`，旁边各有一条 20 秒就走完的死路。

**合格：** `入口 → 中央大厅 →（上层仓库 / 下层废料坑 / 主线厂区）→ 机关互相影响 → 解锁环形通道 → 返回中央大厅`。

### 3.3 难度与引导节奏

每关遵循：**看见 → 单独练习 → 组合考验 → 独立判断 → 奖励与捷径**。

- 先用地图形状讲解机关，不要一进门就给大段说明文字。
- 关键机关必须避免软锁：推错重石、提前击败敌人、掉进单向井之后，都应有合理恢复机制。
- 主线岔路控制在“有选择、但能推理”的范围；秘密路线可以更难。
- 玩家卡住时给予 **渐进提示**：第一阶段环境暗示，第二阶段目标文字，第三阶段可主动请求提示；不能每隔十秒强制剧透。

## 4. 六关独立空间设计

### 01 / BOOT · 启动区｜“认识岔路”

- **空间主题：** 废弃启动机房，中央电源大厅、上层维护通道、下层线路井。
- **结构：** 一条清晰主线 + 一个容易发现的上层岔路 + 一个先见后开的地下门。
- **复用玩法：** 推箱压板、攀梯、开启动宝箱、终端回血、前往 ARCHIVE。
- **记忆点：** 中央巨大电源指示环与逐渐点亮的灯带。
- **回环：** 解锁上层折返梯；后期 RECYCLE 修复后再打开回访捷径。
- **目标：** 新玩家第一次理解“支路不是错误路线，返回还有意义”。

### 02 / ARCHIVE · 档案仓库｜“纵向书架迷宫”

- **空间主题：** 多层档案书架、被封存的目录夹层、破损记录仓。
- **结构：** 下层归档大厅 → 中层错位书架 → 上层检索桥；两侧可绕行，隐藏夹层藏可选宝箱。
- **复用玩法：** 重石压 WEIGHT 2、数据虫、可破碎障碍、档案密钥与持续信号。
- **记忆点：** 一整面高耸档案柜、会升降的检索平台。
- **回环：** 推下重石后可从另一侧降到大厅，而非原路返回。
- **目标：** 首次产生“原来上面还藏着一层”的纵向探索体验。

### 03 / POP-UP · 弹窗区｜“错位与路径变形”

- **空间主题：** 重叠窗口、失控广告回廊、竖向缓存井。
- **结构：** 中央弹窗大厅分为上方叠窗道、下方缓存道；两道可在保险丝室汇合。
- **复用玩法：** 飞蛾弹反射、导流片、保险丝与恢复供电；保留飞蛾被提前击败时的备用方案。
- **记忆点：** 可变形的巨型弹窗边框、滑动窗口地板。
- **回环：** 供电恢复后打开直达大厅的窗口夹层捷径。
- **目标：** 地图路线随机关状态变化，但新手能从视觉变化推理道路。

### 04 / RECYCLE · 回收站｜“三层工业回环” **第一优先样板**

- **空间主题：** 分拣大厅、上层吊装轨道、地下废料坑、磁吸井、重构台。
- **结构：** 明确的三层探索空间，至少两条不同路线可最终回到中央大厅。
- **复用玩法：** 可反向输送带、SAFE STOP 压机、磁吸钢块、指定可破碎板、WEIGHT 2、三片固定通信数据、修复后暗道、两宝箱。
- **记忆点：** 大型垂直磁吸吊机与跨区域运输轨道。
- **回环：** 下层磁吸井 → 侧面维护井 → 上层吊装轨道 → 中央大厅；后期开回 BOOT 捷径仍保留。
- **目标：** 展示为什么“地图结构”比“多放五台机关”更好玩。

### 05 / SIGNAL · 信号中心｜“三路互相影响”

- **空间主题：** 三座信号塔、绝缘水道、继电蜂桥、垂直光纤井。
- **结构：** 中心诊断台为 HUB，A/B/C 三支路可分顺序探索，最终汇合顶部主光纤端口。
- **复用玩法：** ARCHIVE 的真实持续信号、POP-UP/RECYCLE 修复信号、蜜蜂临时导电、鳗电脉冲、水道绝缘和旁路存档。
- **记忆点：** 三根分立的大型发光信号柱，逐个点亮。
- **回环：** 完成每支路后都能打开直通诊断台的快速返回门。
- **目标：** 玩家清楚理解三路状态；`READY` 不等于消息已送达。

### 06 / ERROR · 错误核心｜“中心 Boss + 环形解谜”

- **空间主题：** 破碎处理器核心、外圈三条故障线路、活塞走廊、诊断站。
- **结构：** 以中央核心为可见地标，外圈多个路径围绕它；三条护罩线路都通向核心，但彼此可通过回环连通。
- **复用玩法：** 重物解除 A、反射弹解除 B、反接真实 SIGNAL 脉冲解除 C、最终核心开关与三阶段故障机蝉。
- **记忆点：** 多层可见的核心反应炉，随着三路修复逐渐稳定。
- **回环：** 每修一条护罩线路就解锁回中心的捷径，避免重走长走廊。
- **目标：** 把已学习的机制组织成可读的空间挑战，而不是死记按键与条件。

> 六关主色应沿用 `data/screen_manifest.json` 的现有屏幕身份色，以关卡内材质、灯光与地标深化，不应六关随意换色造成新的识别混乱。

## 5. RECYCLE：第一阶段可玩样板，具体拓扑

### 5.1 节点草图（“位置关系”而非最终美术）

```text
                ┌───────────────上层吊装轨道 [U]──────────────┐
                │                     │                      │
       上层观察台 [O]            隐藏零件 [H]             捷径梯 [S]
                │                     │                      │
入口 [E] ── 中央分拣厅 [C] ── 压机工段 [P] ── 重构终端 [R] ── 出口
              │      ↖____________________________________↗
              │                       开门后回环
        地下废料坑 [D] ── 磁吸井 [M] ── 维修竖井 [V]
                            │                │
                        隐藏宝箱 [T] ───────┘
```

逻辑要求：

- 入口 `E` 很快来到中心 `C`，能看见但暂时进不去的上层 `U` 或目标 `R`。
- `C` 至少有 **向前、向上、向下** 三个真实选择，不能只是三扇黑屏传送门。
- 沿下层 `D → M → V` 完成磁吸解谜后，获得通向上层 `U` 的新道路。
- 沿上层 `U → P` 完成压机 / 输送带联动后，可从侧面抵达 `R`。
- 主目标三片数据分散在具备不同操作意义的区域；**不许为了凑三片而复制三次同一个谜题**。
- 打开 `S` 后，返回中央大厅的路径显著缩短，产生“原来这里是相通的”反馈。
- 原有 `sorter / well / cache / tunnel` 等房间 ID 与存档兼容需通过迁移层处理；不要直接改名后丢失老存档物件状态。

### 5.2 地图可视化目标

- 游戏画面仍是 **320×240**，但世界画布可远大于一屏，通过镜头滚动呈现；同一物理探索区建议至少达到 **多屏宽、两屏以上高**，实际数值由相机与关卡物理测试决定。
- 至少存在一处玩家站在中层时能 **看到上层通路的一部分**，从而激发探索。
- 重要岔路用地形、灯光和声音区分；不要只贴上 `UP/DOWN` 箭头。
- 隐藏宝箱不能直接摆在主路，必须经过观察、绕路或解谜才能拿到。
- 主线每完成一大步都能看见实际环境变化，例如输送带换向、废料门升起、维修梯落下。

### 5.3 走通的示例玩家路线

`入口 E → C（看见上方封闭通道） → 下层 D（收集第一片） → M（磁吸钢块解谜，获得第二片） → V（通往上层的竖井） → U（俯瞰先前区域） → P（压机停止/安全通过，第三片） → R（重构数据） → 捷径 S 打开 → C（回到熟悉地点） → 出口`。

隐藏分支 `M → T → V` 允许可选探索；玩家漏了隐藏宝箱仍能通关。

### 5.4 RECYCLE 样板验收（必须实机操作）

- 在**不切换 CRT** 的情况下，玩家能连续体验一段明显的纵向镜头跟随。
- 真实存在一个三岔口，且至少两个选项通往不同空间内容。
- 玩家能绕一圈回到自己认识的中央地标，而不只是沿路退回。
- 解谜失败能重试；敌人或石块不会堵死唯一出口。
- 两处关键节点能让玩家通过环境线索判断目标位置。
- 原三片数据、两个宝箱、信号修复和通向其他 CRT 的逻辑保持正确。
- 提交 **完整探索路线录像** 与 **地图拓扑对照图**，不能只提交一张漂亮的新场景截图。

## 6. 技术改造要求（Godot 4 / GDScript）

### 6.1 必须先修的“硬限制”

1. **地图尺寸配置化：** 修改 `RoomCatalog.valid_room()` 中的宽高上限，改成合理的引擎安全范围与资源预算。不要只把 `256` 换成一个巨大的常量；配合实际关卡边界、出生点、机关坐标验证。
2. **统一坐标校验：** `SideWorld.point()` 目前静态限制 X/Y；应在关卡加载时根据 `world_size` 校验实际实体坐标，并更新所有调用点。不要把地图外坐标静默当作 `Vector2.ZERO`。
3. **镜头真正跟随 Y：** 重写 `_snap_camera()`，支持横纵跟随、相机边界、缓动、提前量与安全区域；人物跳跃/攀梯时不抖动，跌落时能及时看见落点。
4. **保留 320×240 视口：** 只增大 **world 坐标范围**，不增大游戏显示分辨率；依旧使用最近邻像素渲染。
5. **所有载入/切换/恢复路径一起修：** `main.gd` 中的出生点范围、存档位置、跨房间进入检查、阻挡检测、死亡复活、R 复位和相机重置都要适配大地图。
6. **相机和实体安全：** 不许露出地图外黑边；摄像机不能穿过不可见边界；镜头变换不得让玩家在 320×240 画面中失踪。
7. **大型地图性能：** 脱屏敌人/特效合理降频，减少没有必要的逐帧绘制和重复背景节点。不要用每房间一个高分辨率独立 SubViewport 解决问题。

### 6.2 房间连接：从线性列表升级为空间图

- 为每关维护 `room_id / area_id / floor_id / connection_id / portal_id` 等明确身份；连接必须有 `from → to`、出生点、方向、解锁条件、返回路径。
- 支持同一区域多入口与循环连接，不能假定每房只有“左入口/右出口”。
- 端口只能到明确存在且可安全落地的出生点；新旧房间映射迁移必须可回退。
- 防止“门已开但返回时仍锁定”“右端进入却从左侧错误位置出生”“一进门又自动触发原端口”等问题。
- **世界地图的空间关系** 与 **房间端口数据** 需源自同一组连接定义，避免图标显示一条路而实际走不通。

### 6.3 存档与剧情兼容

- 不能丢失原 v4 进度、角色外观、宠物收藏、九宝箱、六屏修复、当前信号条件和结局状态。
- 大地图上线需设计 **版本化迁移**：旧 `room_id + position + block positions` 逐项映射新结构；无法精确映射时仅将位置送到该关安全检查点，不能假装机关已经完成。
- 迁移前自动备份；迁移失败不覆盖源档；新游戏与继续游戏分别回归。
- `ARCHIVE` 的 WEIGHT 2 持续信号、`SIGNAL READY`、`ERROR` 的三节点与最终送达事务必须保持原有语义。

### 6.4 新增导航状态数据

建议单独保存：

- `visited_areas`：已进入区域。
- `discovered_connections`：已实际见过/走过的通路。
- `opened_shortcuts`：永久开启的捷径。
- `current_area` 与 `last_entry`：当前区域和来源。
- `hint_seen`：已经读过的提示，避免重复弹出。

上述字段为**建议结构**，应融入现有存档框架，避免与已有 flags 重复或产生两套权威状态。

## 7. 视觉设计：空间层次感从哪里来

这里说的“纵深”不是再加十个背景装饰，而是要有空间结构。

- **近景层**：少量遮挡边缘的管线、栅栏、柜体，不能覆盖角色或重要机关。
- **游玩层**：平台、桥、梯子、落点、操作机关的所有有效碰撞平面。
- **远景层**：能暗示更高更低空间的竖井、机器剖面、书架和走廊窗口，带低速视差。
- **统一识别**：六关延续既有主色，但主路径、危险区、可互动区形成一致视觉语法。
- **每个分区地标**：最好使用不同的形体语言，而不是每个路口都只放一个同样的箭头牌。
- **阴影与可读性**：优先让角色、危险、机关一眼分开；不靠强 Bloom、粗糙霓虹或随机文字堆料。

**强制要求：** 任何背景层、远景平台都不得误导玩家认为可站立或可攀爬。场景装饰与真实可走路线之间有可辨的材质/边缘差异。

## 8. 实施计划：先 RECYCLE，再六关

### 阶段 A / 设计审计与拓扑图（不得直接开始摆场景）

- 读取现有六关 JSON、端口关系、机关行为、存档、相机和 QA 测试。
- 输出每关 **旧地图拓扑图**：区域、出口、门锁、宝箱、关键旗标、回访条件。
- 输出每关 **新地图拓扑图**：主线、分支、回环、垂直层级、主/选做路线。
- 明确哪些房间原 ID 保留、哪些新增、迁移策略是什么。
- 验收：新图比旧图明显多出“可走回路”，而非只是更多节点。

### 阶段 B / 地图底层能力改造

- 改尺寸限制、坐标函数、镜头、边界、出生点、存读档兼容。
- 新增结构化导航数据，但不重画六关全部美术。
- 建立一个空白测试大地图，验证上下移动、掉落、梯子、传送、死亡、R 复位。
- 验收：320×240 正常，镜头上下跟随流畅，旧关无新增崩溃。

### 阶段 C / RECYCLE 完整可玩样板

- 按第 5 节完成三层、分岔、回环、捷径、地标、三片数据、两宝箱与修复出口。
- 给出正常推进路线和可选探索路线，并做人工实机走关。
- 优先保证玩法与路径体验；通过后再精修工业美术。
- 验收：可从入口完整探索至出口并回访支路；录像证明存在真实回环。

### 阶段 D / 其他五关各自重构

- BOOT、ARCHIVE 先保证新手学习坡度；POP-UP、SIGNAL 体现空间机关；ERROR 做综合回环。
- 每关保留既有故事关键事件与九宝箱总数；新增奖励不能破坏已有经济和平衡。
- 随同增加当前关卡内部地图、状态、入口/出口标识。
- 验收：六关的布局轮廓不能是同一模板换色。

### 阶段 E / 性能、存档与交付

- 六关从新游戏连续实走至送达结局；回访、全九箱、旧存档迁移、Boss 复战状态。
- 1280×800、720×900 等既有窗口回归；窄窗口不代表真正手机触屏已完成。
- 对比新旧性能、内存、加载时间；新的大地图必须测实际 GPU，而不是只看 headless passed。
- 提交截图、视频/动图、数据清单、QA 结果及已知限制，不用概念图冒充真实画面。

## 9. 核心验收清单（Codex 不可只提交“完成”）

- [ ] 六关均有 **明确的主线 + 有价值的支线**，而不是全都横向直走。
- [ ] 至少 RECYCLE 样板具备 **明显的三层空间、真实三岔口、至少一条回环捷径**。
- [ ] 真实镜头随玩家上下移动，世界高度不再由 256 的硬限制卡死。
- [ ] 320×240 像素视口及 3D CRT 外壳保持原样；Clawd 不出屏幕。
- [ ] 每条端口都有一致的来源/去向信息与可返回逻辑。
- [ ] 关卡内部地图与 Tab 电脑阵列地图各司其职。
- [ ] 玩家在关键岔路能识别地标，重要机关和隐藏区域有空间线索。
- [ ] 所有旧机关、六段信号、九宝箱、Boss、结局条件保持正确。
- [ ] 旧档保留与迁移有实证；失败能回退，不覆盖进度。
- [ ] 每关提供旧/新拓扑图、实机截图与真实行走路线；至少 RECYCLE 提供全程录像。
- [ ] 通过脚本自动化 + 人工首次游玩测试；不得只用自动 QA 声称“不会迷路、已经好玩”。

### 建议人工试玩观察项

- 玩家能否在 **1 分钟内说出当前位于哪关、哪层、眼前目标是什么**。
- 分岔是否真正引发探索，而不是看到死路立即折返。
- 玩家打开捷径时能否意识到“回到曾经到过的地方”。
- 迷路后能否利用地标或地图自行找回主线。
- 同一个机关是否被过度重复；有没有长时间纯跑路。

这些是**体验评估指标**，不是声称当前已经测得的事实。
