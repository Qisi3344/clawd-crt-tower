# 《CRT小蟹闯塔记》操作模式选择与渐进式新手教程策划书

**版本**：v1.0｜2026-11-08  
**用途**：交付 Codex，在现有 Godot 项目上直接开发，不另建游戏  
**GitHub**：https://github.com/Qisi3344/clawd-crt-tower  
**工程目录**：`CRT_CRAB_Code/crt_crab_devkit/`  
**引擎**：Godot 4.x / GDScript / OpenGL Compatibility（仓库记录使用 4.7.2）  
**本次范围**：仅 **键鼠操作、触屏操作**，以及与之对应的菜单、交互、提示、教程、视口适配、设置和验收；**不新增手柄开发任务、手柄选项或手柄教程**。

> **开工前事实校验（以 2026-11-08 已推送仓库为准）**：原版已经不只是 BOOT + ARCHIVE 两屏切片。仓库 `main` 已包含 BOOT、ARCHIVE、POP-UP、RECYCLE、SIGNAL、ERROR **六关可玩首版**，主动修复通信的桌宠开场、消息送达结局、六类屏保解锁动画、三阶段 Boss、多房间及跨屏联动。存档已是 **v4**。本策划属于**在这些功能上补操作体验**；严禁把六关、开场、结局和解锁动画当待重做模块。核对 `docs/SIX_LINK_PROGRESS.md`、最新 README 后再修改。

## 1. 产品目标与核心决定

**目标**：任何第一次接触游戏的人，在点击「开始游戏」后选择自己的操作方式，观看 Clawd 主动进入系统修复通信的开场剧情，然后在 BOOT 中通过自然操作学会移动、跳跃、交互、推拉和攀爬；后续六关只在首次出现新能力、新机关时给予短提示。

**体验原则**：

1. **只出现两个选项**：「键盘 + 鼠标」「触屏操作」。不出现手柄、控制器配对等第三项。
2. **第一次选择、之后记住**：首次开始/旧存档首次继续而无操作偏好时弹出选择；以后不重复询问，但主菜单设置、暂停设置中始终可更改。
3. **选择发生在开场之前**：`点击开始游戏 → [首次]选操作方式 → 原开场动画 → BOOT 教程 → 正常闯关`。这样开场中的「跳过」按钮也能适配触屏。
4. **轻提示而非说明书**：同屏只显示一个当前需要学会的操作；实际成功执行才标记教学达成，不靠点击「知道了」通过。
5. **一个游戏逻辑，两套输入**：都驱动现有 `move_left/right/up/down`、`jump`、`attack`、`interact`、`overview`、`pause`、`reset_puzzle`，不能写两套移动、战斗、机关代码。
6. **不牺牲画面可读性**：保留单个 `320×240` 的 2D 可玩视口和外层 3D CRT 阵列；触屏控件不遮住角色、箱子、压板、传送口及关键提示。
7. **不强制重新开档**：已经开始或已经通关的玩家保留剧情、九箱、外观、扭蛋收藏、机关状态和六屏修复进度。

**明确不做**：手柄界面、按键重映射系统、增加新关卡/新怪物、新战斗能力、联网聊天、把 3D 外围空间变成可操作地形、依赖宣传视频代替游戏内可跳过的剧情。

## 2. 首次进入与返回流程

### 2.1 主菜单逻辑

| 玩家情形 | 点击入口 | 预期行为 |
|---|---|---|
| 首次打开/没有控制偏好 | 「开始游戏」 | 先打开操作选择页；确认后走当前 `begin_adventure(true)` 与原开场；取消则返回主菜单，不改存档 |
| 有旧存档、无控制偏好 | 「继续冒险」 | 先选操作方式，再按原存档继续；不得重置、不得强制重播开场 |
| 已保存控制偏好 | 「继续冒险」 | 直接进入现有进度；不再询问、不重播看过的剧情 |
| 已保存控制偏好 | 「新游戏」 | 沿用原二次确认及备份流程；操作偏好不清空；剧情按现有新游戏规则重新播放 |
| 运行中 | 「暂停 → 操作设置」 | 随时切换键鼠/触屏；立即更新提示和控件；不更改谜题和角色位置 |
| 回到主菜单 | 「设置 → 操作方式」 | 可以主动改选；不影响下一次继续游戏 |

**实现注意**：目前 `front_end.gd` 的「开始游戏/继续冒险/新游戏」按钮直接调用 `game.begin_adventure(...)`。需要在外侧接入统一的 **控制偏好检查/选择流程**，但保留原 `begin_adventure` 的存档验证、进关、开场播放顺序。不要先执行 `save.new_adventure()` 再让玩家选择；否则玩家在选择界面取消也可能清空进度。

### 2.2 操作选择页（UI 文案）

```text
┌─────────────────────────────────┐
│           选择操作方式          │
│       之后可在设置里切换         │
│                                 │
│  ┌──────────┐  ┌──────────┐     │
│  │  ⌨       │  │  ▣       │     │
│  │ 键盘+鼠标 │  │ 触屏操作 │     │
│  │ 电脑游玩  │  │ 手机/平板│     │
│  └──────────┘  └──────────┘     │
│                                 │
│       [ 确认并开始冒险 ]        │
│              返回               │
└─────────────────────────────────┘
```

- 设计延续现有复古 CRT 像素 UI：深色底、清晰的像素轮廓、有限的青绿/梅紫点缀；不能另做商务蓝设置页，也不要用单薄 SVG 图标敷衍。
- **默认高亮可猜，但必须让玩家改选**：可根据运行平台及触摸能力建议触屏；桌面默认键鼠。注意 Windows 触控笔记本和「模拟鼠标触屏」可能误判，不得强制。
- 点击「确认并开始冒险」才写入操作偏好；「返回」不写入偏好、不启动剧情、不写新存档。
- 用原生 UI 控件可键鼠、触摸点击；状态色/焦点清晰；窄窗口不溢出。默认不需要帐号或网络。

### 2.3 和开场/结局、解锁动画的衔接

- **开场**：继续使用 `StoryDirector` 现有的约 15 秒剧情，Clawd **主动按 REPAIR、主动跳入系统**，不能改成被动吸入或发生故障后莫名传送；不额外新建第二段视频。
- **开场触屏跳过**：提供明显但克制的「跳过剧情」按钮；按住/点按规则以当前故事导演为准。不要只依赖 Esc。
- **开场键鼠跳过**：保留现有 Esc；按钮也可鼠标点击。剧情暂停/失焦/跳过后正确回到 BOOT。
- **屏幕解锁动画**：复用 `ScreenUnlockDirector`，保留六种屏保演变（锁扣、波纹/干扰、节点、电路等），首次进入才播放。触屏有「跳过」入口，键鼠保留现有跳过键；输入锁定不触发攻击/跳跃。
- **结局**：复用既有 User「还在吗？」发送成功、Clawd「在呀！我回来啦！」的演出和继续探索入口；切换输入模式不影响 `story.intro_seen/outro_seen`、`message_delivered`、`screen_unlock_seen`。

## 3. 两套控制的统一动作表

| 游戏行为 | 键鼠模式：沿用已实现绑定 | 触屏模式：新增表现 | 注意事项 |
|---|---|---|---|
| 左右移动 | A / D 或 ← → | 左侧圆形虚拟摇杆左右 | 保持连续移动，不是格子跳格子 |
| 攀爬梯子 | W / S 或 ↑ ↓ | 摇杆向上/向下（靠近梯子时） | 只有在梯子区域生效，不变成自由飞行 |
| 跳跃 | 空格 | 右侧「跳」键（持续点按可触发跳跃缓冲） | 不改变现有跳跃手感 |
| 螯击 / 破坏 | J / 鼠标左键 | 右侧「螯击」键 | 攻击范围、冷却统一 |
| 交互 / 开箱 / 终端 | E 或 K | 右侧「互动」键 | 接近物品时明确高亮当前目标 |
| 推/拉箱石 | 按住 E/K + A/D；拉时保持朝向箱石 | **按住互动键 + 摇杆朝推动/拉动方向** | 放开即停止；不另放第 4 个永久「推拉」按钮 |
| 查看电脑塔 | Tab；鼠标拖动环绕/滚轮调高度 | 顶部「阵列」按钮；拖动旋转，双指滑动调高低或用屏内 ± | 观察时隐藏战斗键，保留返回箭头 |
| 暂停 | Esc | 顶部「暂停」按钮 | 可切换输入方式、查看操作帮助 |
| 重置当前房间谜题 | R | 暂停页「复位当前谜题」 | 必须二次确认（触屏易误触），保留宝箱、永久奖励和故事进度 |
| 跳过开场 / 解锁演出 | 原 Esc / E 等既有操作 | 「跳过剧情」「跳过动画」点击目标 | 不把跳过判成 J/E 的游戏操作 |

> 已有 `main.gd` 中还注册过其他输入映射。**本次不开发、不展示、不测试其他操作设备的界面**；已有兼容代码除非与本功能冲突，不必破坏性删除。不要误把「本次不做」理解为删除全部相关底层代码。

### 3.1 「互动」键的上下文优先级（必须统一）

一次操作只选一个有效目标，避免「想推箱却开了旁边宝箱」。建议优先级：

1. 已处于推/拉状态且按住互动 + 方向 → 继续推拉。
2. 面朝、近距离、可推拉的箱石 → 互动按住 + 方向优先触发推/拉。
3. 未按方向且可交互目标高亮 → 单击互动打开宝箱/使用终端/进入端口。
4. 无有效目标 → 不发生行为，必要时轻提示。

- 推拉用**长按状态 + 方向**，不要让玩家为了推箱去连续狂点。
- 现有 `SideCrab.try_push()` 依赖角色 `facing`，拉动时面向箱石不能随摇杆改变朝向；复用原规则并测冲突。
- 触屏长按互动时，弹窗不要抢走左手移动触点；离开屏幕、切换界面、失焦都必须释放按键状态。
- 不能为触屏偷偷增加自动解谜或扩大攻击命中范围，两个模式规则一致。

## 4. 触屏 HUD 与实际可玩空间

### 4.1 布局原则

**横屏优先，竖屏也不直接消失或不可操作。** 适配使用安全区域和实际视口尺寸，不准只拿 720×900 的桌面窗口截图冒充 iPhone 触屏验收。

**横屏布局**：

```text
╔══════════════════════════════════════════════════════╗
║ 血量 / 任务                                 阵列  暂停║
║                                                      ║
║               正在玩的 CRT 屏幕                      ║
║           [  小蟹 + 地形 + 机关  ]                   ║
║                                                      ║
║  ◎ 方向摇杆                           [跳]  [螯击]    ║
║                                        [互动]         ║
╚══════════════════════════════════════════════════════╝
```

**竖屏布局**：

```text
┌───────────────────────┐
│任务/血量        阵列 暂停│
│                       │
│      CRT 关卡画面      │
│   （较大比例、居中）    │
│                       │
├───────────────────────┤
│  ◎ 摇杆       跳 螯击  │
│                互动    │
│                       │
└───────────────────────┘
```

- 3 个主动作键：**跳跃、螯击、互动**。摇杆支持上下左右；不再挤入默认复位、换装、扭蛋等按键。
- 「阵列」「暂停」放顶部边缘，不挡关键场景；「复位」进暂停菜单；剧情期间显示专用跳过键。
- 左右控件提供清晰的实心触摸区域，视觉风格为像素按钮 + 立体按下反馈，禁止透明到找不到按钮；不用系统默认灰色 UI 堆起来。
- 按键视觉大小建议至少约 **48–56 逻辑像素/点等效触达区域**，重要动作可以更大，最终以实机手指可触达验证为准。与系统边缘手势区留安全边距。
- 两指同时操作为必需：左手摇杆移动 + 右手跳/互动；支持拖动摇杆不抬手转向。布局要能完成「攀梯 + 攻击」「推箱 + 移动」「移动 + 跳跃」。
- `SubViewport(320×240)` 仍是唯一实际运行的 2D 世界；改变的是**外层显示区域、聚焦镜头与控件叠层**，不要为了手机重复生成第二个 SideWorld。
- 竖屏无法完整展示时优先增大当前 CRT 可玩显示区、缩减非必要外部 3D 布景露出比例；而不是把角色缩小。禁止裁切玩家前方的机关线索。
- 横/竖切换后重新计算屏幕和控件布局；不得使角色、碰撞体、镜头、输入坐标、UI 选中状态失效。

### 4.2 阵列观察状态

- 点击「阵列」时：隐藏摇杆、跳跃、螯击和互动键，打开现有 3D CRT 阵列观察（已有 `ShellDirector`）；顶部显示「返回闯关」。
- 单指水平拖动旋转，纵向拖动/双指滑动调整观察角度；与当前镜头逻辑兼容且可限制俯仰范围。
- 阵列内已有的六屏状态面板、解锁与修复信息继续显示，不新造选关捷径。若当前屏幕不可传送，观察模式不能越权直接进入其他关卡。
- 返回闯关时，恢复控件和原 2D 角色状态，不得额外计入角色步数或播放跳跃。

### 4.3 操作模式切换的清理

- 切出游戏到暂停/菜单/剧情/解锁动画/扭蛋界面时，虚拟摇杆与按钮**立即释放**；不会让小蟹恢复后自动向一侧跑。
- 切到键鼠模式时销毁或隐藏触屏 HUD 的捕获区，避免无形覆盖菜单鼠标点击。
- 鼠标左键现被映射为攻击：触屏 UI 点击不可通过「模拟鼠标」意外触发攻击。检查事件被 GUI 消费、触屏映射与 `Input.action_press` 的边界。

## 5. 新手教学：由场景触发、实做验证

### 5.1 展现形式

- **位置**：贴着当前任务附近的一个小提示条，或安全的屏幕边缘；玩家仍看得到角色、陷阱、机关。
- **内容**：一行短文字 + 对应操作的实际按钮小图示。例如键鼠：「A / D  移动」；触屏：「拖动左侧摇杆  移动」。
- **消失条件**：正确动作达成（走动一定距离、成功跳过沟壑、实际触发板/完成开箱），而不是时间一到就消失。
- **避免烦人**：同一教学不反复跳出；失败/死亡时允许轻量再次提示；设置里可关闭、重新查看；对有经验玩家提供「跳过新手指引」。
- **人物感**：Clawd 可歪头、挥钳、在头顶冒一个问号或成功反馈，但不增加长篇台词、不打断操作、不用巨大弹窗替代教学。
- **模式自适应**：从键鼠换成触屏，下次触发相同技能提示时显示触屏图标；反之同理。操作方式切换不会重置已完成的关卡谜题。

### 5.2 教程路线表

| 教学 ID / 阶段 | 触发条件 | 键鼠提示 / 触屏提示 | **成功判定** |
|---|---|---|---|
| T01 BOOT-移动 | 进入 BOOT 第一段可玩区域且未学会 | 「A/D 移动」 / 「拖动摇杆移动」 | 角色确实水平位移一段安全距离，非只按下键 |
| T02 BOOT-跳跃 | 靠近第一个小沟，未学会 | 「空格 跳跃」 / 「点击 跳」 | 成功起跳并落到沟对面安全平台 |
| T03 BOOT-推箱 | 到启动箱石位置，未学会 | 「按住 E + 方向 推箱」 / 「按住互动 + 摇杆 推箱」 | 箱子被实际推到压板，门开，不能靠触摸按钮直接过关 |
| T04 BOOT-攀梯 | 首次进入梯子有效区域 | 「W/S 攀梯」 / 「摇杆上下 攀梯」 | 到达梯子顶部安全平台 |
| T05 BOOT-开箱 | 靠近第一个未开宝箱 | 「E 开箱」 / 「点击互动 开箱」 | 宝箱唯一领取标志正确写入；重复接近不再教 |
| T06 BOOT-进入下一 CRT | 靠近已具备条件的 ARCHIVE 端口 | 「E 连接」 / 「点击互动 连接」 | 实际安全完成跨屏传送，首次解锁动画照常播放 |
| T07 ARCHIVE-螯击 | 第一次靠近数据甲虫或裂纹块 | 「J 螯击」 / 「点击螯击」 | 确实击中敌人或破坏可破墙，不把空挥钳算完成 |
| T08 ARCHIVE-重石 | 玩家看到重量 2 压板或重石 | 「把重石送到 WEIGHT 2」 / 模式一致，仅按钮不同 | **重石真正压住**压力板，连通跨屏信号 |
| T09 机关软锁 | 首次将箱石推入不能继续的死角或玩家主动复位 | 「R 复位谜题」 / 「暂停 → 复位当前谜题」 | 当前谜题正常恢复，宝箱和永久奖励不丢失 |
| T10 阵列查看 | 首次出现需要跨屏回访的任务，或玩家首次按 Tab | 「Tab 查看阵列」 / 「点击阵列查看线路」 | 进入阵列并返回正常游玩 |
| T11 后续新机关 | POP-UP / RECYCLE / SIGNAL / ERROR 首遇新机关 | 不教完整解法，只教操作和可见规则 | 玩家完成一次真实规则互动；可失败重试 |

**特殊规则**：当前六关已完成，不得为了塞教程而删除关卡、放大简单机关或插入强制封锁区。通过原有位置、区域 ID、物体 ID、旗标、信号和交互事件触发提示；不足的埋点增设小型事件，不要重写 SideWorld。

### 5.3 后四关教学递进

- **POP-UP**：弹窗飞蛾攻击有蓄力预警；提示「改变导流片方向，让错误弹命中保险丝」，但不直接画出全解路径；击败飞蛾后已有备用脉冲解法仍然有效。
- **RECYCLE**：第一次出现输送带提示可反向；压机有 SAFE STOP；磁吸钢块是新规则，首次吸附时显示一次操作提示，后续不再刷屏。
- **SIGNAL**：三路 A/B/C 输入由不同 CRT 供给；提示来自已修复的真实状态；蜜蜂的暂时导电、绝缘水道等只介绍规则，玩家自行组合。
- **ERROR**：避免 Boss 战中出现大幅遮挡的教程弹窗；危险招式先以视觉预警教会，再在安全段给一行「可利用重物/反射弹/外部信号反击」提示，后续让玩家实战。

### 5.4 教程交互优先级

1. 危险预警（当前会受伤）高于教程提示。
2. 当前可交互物提示高于冗余基础按键教学。
3. 解锁动画 / 开场 / 结局 / 传送正在播放时，不出现普通关卡教程。
4. 暂停与阵列观察时，教程时钟暂停；返回后根据有效状态恢复，不能自动误判完成。
5. 旧存档若已经完成 BOOT/ARCHIVE 的相应收集和关键旗标，不追着玩家补放低级教程；第一次切换到触屏可弹一次 2–3 秒的简短「触屏按键位置」说明。

**Godot 实现提醒**：

- `DisplayServer.is_touchscreen_available()` 可用于建议默认模式，但不等于一定在手机，也不能完全决定 UI；最终始终听玩家手动选择。
- 触摸按键可考虑 `TouchScreenButton` 的多点触控能力；摇杆可用自定义 `Control`/`Node2D` 接收 `InputEventScreenTouch/Drag`，**要记录每根手指的 index**，保证多指同时按。
- 将触屏输入映射回现有 InputMap 的 action，不复制物理规则；切换状态/失焦/取消手势时对注入的 action 做完整释放。留意不同物理来源同时按同一 action 的情况，不能误清掉键盘正在按的键。
- Windows 测试可启用模拟触摸作**开发测试**，但不能替代 Android / iPhone 上的真实触摸验证。
- `main.gd` 当前含 `StoryDirector`、`ScreenUnlockDirector`、传送期间锁定、暂停和阵列状态；**任何模式切换都不得使这些状态机互相覆盖**。

## 7. 存档与配置策略

### 7.1 操作偏好（独立配置）

建议放在 `user://controls.cfg`（独立于冒险存档）：

```ini
[controls]
profile="keyboard"      ; 只允许 keyboard / touch
profile_chosen=true
show_tutorial=true
```

- 不存手柄字段；读取到未知值回退为未选择，且不自动删除进度。
- **新游戏不会清空操作偏好**；玩家设置后立即保存；保存失败给明确反馈，不假装成功。
- 没有历史配置时推断推荐值，但必须确认后才记录。

### 7.2 新手教程进度（随冒险存档）

建议在冒险存档新增可选结构：

```json
"tutorial": {
  "completed": ["T01", "T02", "T03"],
  "skipped": false,
  "mode_hint_seen": {"keyboard": true, "touch": false}
}
```

- 若改动 `progress.json` 的版本化格式，严格进行 **v4 → 新版本**迁移；保留 `story`、`screen_*`、六关世界数据、全部宝箱和旗标，写入失败禁止覆盖旧档。
- `new_adventure()` 应重置教程完成记录，但保留 `controls.cfg`；「继续冒险」读取当前已完成教学；已通关存档不应把 T01～T06 当新任务弹出来。
- 「关闭教程」默认仅关闭主动提示，不锁技能、不锁端口、不影响剧情；暂停中「查看操作指南」仍然可用。
- 重播教程可提供「查看全部操作说明」或「重置教学提示」入口，**不能因重播而清空关卡进度**。

## 8. 体验细节和错误处理

1. **操作选择取消**：必须返回上级界面，原存档字节不改变。
2. **控制模式改变**：不能瞬间重启关卡、传送到 BOOT、清空箱石或重播开场。
3. **多点触控**：一根手指摇杆，第二根按跳跃，第三根可按互动；第一根抬起只停止移动，不清掉另一根仍按着的动作。
4. **手机系统返回 / 切出应用**：暂停并释放虚拟输入；恢复不把旧触摸当按住。
5. **重复点击 / 多指点按钮**：同一剧情跳过、菜单确认或传送不得触发两次。
6. **横竖旋转**：重新布局，现有同一个 SideWorld 不重启；当前 CRT 相机要保证角色与当前机关可读。
7. **场景遮挡**：触屏按钮不能挡住飞蛾弹道、重量数值、蜂节点、Boss 预警。必要时可把按钮排到画面外的专门操作带。
8. **不支持移动平台时**：不得显示「手机版已经完成」。Windows 下触屏模拟是 UI 验证，不是手机包。
9. **调试模式**：通过启动参数/QA 夹具明确强制 keyboard/touch，避免 headless 环境因能力检测误进入选择页，导致原自动测试中断。
10. **不触碰扭蛋经济**：宠物扭蛋机、衣橱和晶体已有独立保存规则，切模式不应改抽奖保底、宠物拥有数或外观装备。

## 9. 实现阶段与验收标准

### P0｜先做「键鼠模式选择 + BOOT 教程」

- 在当前主菜单加入选择页，`开始/继续/新游戏` 正确衔接；模式偏好可保存、取消不破坏档。
- BOOT 做 T01～T06 的事件驱动教程；已有开场、解锁动画照常播放。
- 键鼠提示在 HUD、暂停帮助、物体提示三个位置一致；不再一直显示大段 `AD 空格 E J ...` 静态提示。
- 提供跳过教程及重新查看。

**验收**：真实从菜单开始新档，观看/跳过开场，实际走动跳沟推箱攀梯开箱传送，全程无强制说明页，教程记录可保存并恢复。

### P1｜触屏输入层与双模式切换

- 加虚拟摇杆、跳跃、螯击、互动、阵列、暂停与剧情跳过；合并推拉与互动。
- 按输入动作验证多点按住、拉箱不转向、爬梯、连击、触屏菜单不误攻击。
- 设置里切模式立即生效；阵列观察时隐藏战斗按键。
- 横屏和竖屏窗口都能操作；手机安全区域与按钮布局预留适配能力。

**验收**：桌面模拟触屏能完整完成 BOOT→ARCHIVE→BOOT 的原机关，且允许随时切回键鼠；**这只证明触屏逻辑，不代表移动平台发布完成**。

### P2｜后五关教学 + 真实移动端适配

- 给首次出现的新机关做短教学，绝不把完整谜题答案直接剧透；既有六关数据、敌人、Boss 和九个宝箱保持不变。
- 真正运行 Android 或 iOS 构建（若本机工具链限制，明确提供可复现的导出要求和剩余问题）；以真实触摸运行、系统安全区、方向变化为验收。
- 记录机器型号、平台、分辨率、帧耗、UI 可读性，无法实测的项标为未验收。

**验收**：选触屏 → 开场可跳过 → 一直用触屏完成六关与结局（含复杂跨屏联动）；碰撞、推拉和存档不受 UI 模式影响。

### 全回归检查

| 检查项 | 必须通过的结果 |
|---|---|
| 主线保护 | 六关可从 BOOT 通到 ERROR，结局消息正确，仍可继续探索 |
| 跨屏机关 | ARCHIVE 真重石持续供给 SIGNAL A，POP-UP / RECYCLE 连接仍正确，R 重置按原规则处理 |

| 界面 | 桌面横窗/窄窗、移动横屏/竖屏下可点击、无遮挡、可读 |
