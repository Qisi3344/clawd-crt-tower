# CRT CRAB · 给 Codex 的阅读顺序

1. 阅读 `01_CRT_CRAB_场景美术升级执行单_v1.1.md`：既有场景美术规范、建模来源、360° 电脑阵列和屏幕镜头约束。
2. 阅读 `02_CRT_CRAB_游戏玩法开发书_v1.0.md`：侧视像素玩法、机关、跨屏协议、六关设计、数据存储、里程碑和回归测试。
3. **从 M0 仓库审计开始，优先 M1、M2 可玩切片，再进行 M3 美术整合。** 两份文件不是让你创建两个独立工程。

## 场景书审查结论

**原文总体可保留，但必须修订。** 本版保留原作者提供的 3D 阵列、装饰、色板、素材清单和美术验收，作了以下兼容更新：

- “第三人称始终跟随螃蟹”具体拆成 **外部 3D 阵列转场镜头 + 内部 2D 侧视跟随镜头**。
- 使用 BOOT / ARCHIVE / POP-UP / RECYCLE / SIGNAL / ERROR 对齐六台实玩屏幕；GLITCH / MAP / UNKNOWN 作为其他显示状态，而非假的完成关卡。
- CRT 内部建议 4:3（320×240）像素画布，避免强制 16:9 造成拉伸。
- 允许替换旧的屏幕内角色移动与碰撞实现，以兼容新的 2D 侧视玩法，但**保留既有 3D 阵列、可用的路由和数据**。
- 场景负责显示，玩法负责状态，`computer_id` 与 `level_id` 分开；同一时间只有一只可操作螃蟹。
- 增加跨屏条件、持久压力板、错误重试和存档的测试条款。

**没有修改**原文件中未经本次重新核验的 Sketchfab 链接和资产参数；这些仍是候选列表，必须由 Codex 导入前逐项核查授权和下载可用性。

## 首要产出

`BOOT` + `ARCHIVE` 两台实际可玩电脑的完整往返流程：螃蟹侧视走跳、推/拉、重力石块、压力板、机关门、宝箱、一个数据虫、出口转场、持久状态与局部重置。实际验收通过之后才扩充内容。
