# 《屏幕群岛 / CRT CRAB》场景美术升级执行单（v1.1 · 已同步侧视像素玩法 · 交给 Codex）

> 本次任务：基于现有可运行项目进行 **环境美术升级**，同时与《CRT CRAB 游戏玩法开发书 v1.0》保持一致。不推翻已有玩法、不重做为普通房间、不把主角放到电脑外面。参考当前截图：电脑堆叠已存在，但机壳、屏幕内容、线缆、贴纸、空间光照、周边陈列和镜头层次过于统一，整体仍像测试场景。

## 0. 四条不可违背的设计规则

1. **多层、360°立体电脑堆叠是核心视觉**：从各个方向观察均是错落的复古电脑与接线组件；不要收束成一堵电脑墙，也不要用一排显示器替代堆叠。
2. **螃蟹只在各台电脑的「屏幕世界」内活动**：不存在走出屏幕、爬外壳、在底座行走再进入另一台的操作。电脑之间的穿梭是屏幕画面/数字场景转移。
3. **采用双镜头体系，不再要求单一第三人称追尾镜头**：电脑外部使用 3D 过渡/阵列观察相机；电脑屏幕内部使用 2D **侧视正交跟随镜头**，始终以螃蟹为主体。移动、战斗、解谜时屏幕画面足够大、角色清晰可辨；跨屏时 3D 相机短暂后撤、沿阵列移动到目标电脑再推近。主角始终不离开屏幕。
4. **做潮流复古，不做廉价荧光堆砌**：从《绝区零》的街头图形设计、复古消费电子、工业贴纸、层次色彩和材质混搭汲取方法，不照搬游戏商标、角色、原画或独特图标。

## 1. 本次应修改的截图问题

- 当前机壳普遍蓝灰且大小接近，重复感明显。至少做出 4 类外形：方正米白办公 CRT、深色工业终端、彩壳小 CRT、扁宽老式监控/街机型。
- 多块屏幕都是类似「深蓝网格+绿色矩形」，毫无身份差异。正式玩法屏幕依章节使用 **BOOT、ARCHIVE、POP-UP、RECYCLE、SIGNAL、ERROR** 六个关卡 ID；其他未开放的电脑可以显示 GLITCH、MAP、UNKNOWN 等状态，但这些不应冒充已实现的关卡。
- 无装饰的网格地面像编辑器预览，应改为悬浮工业式底座，围绕其增加边缘编号、螺丝、贴带、灯槽；地面不被误认为可行走区域。
- 线缆和连接关系不清晰。增加 3-5 组粗细不同的电缆束，实际连接电脑背面/接口，不能凭空悬停；绕开显示器正面和主角可视区域。
- 当前色块缺乏冷暖与亮暗节奏。补充局部霓虹提示灯、弱屏幕溢光、机壳边缘轮廓光，同时保持大面积深色留白。
- HUD 的荧光黄已有良好标识性，沿用并统一为视觉系统的主强调色；信息面板层级降低，避免遮挡电脑和屏幕。

## 2. 色彩、材质与图形标准

### 色板

- 主背景/结构：#151923（深夜黑） / #293340（石墨蓝灰）
- CRT 复古机壳：#DDD4C2（米白） / #87958D（旧灰绿）
- 主视觉强调：#DCE65B（酸柠黄）
- 次强调：#EA5985（莓果粉） / #54CFC3（电子青）
- 轻量反光：偏冷白，避免大面积暖黄泛旧感。

### 表面细节

- 保留清晰低多边形轮廓，不是粗糙占位方盒子，也不追求写实高面数。
- 局部机壳：细小划痕、变色散热孔、按钮、软盘插槽、螺丝、电源灯、塑料分模线、贴纸残胶。
- 局部标识：丝网印刷感、像素编号、警示三角、剪贴标签、胶带和原创涂鸦；不准满屏随机英文、无意义汉字或大面积粒子。
- 字样示例：`PORT_07`、`NO SIGNAL`、`CRAB LINK`、`ERR//404`、`MEMORY BAY`、`RECONNECT`。这些是原创环境标识，不是直接照搬其他游戏 UI。
- 屏幕：轻微曲面感、局部扫描线、受控的屏幕玻璃反射；**屏幕世界必须始终清楚**，不能为了玻璃效果将螃蟹盖住。CRT 首选 **4:3 可玩画幅（如 320×240 或 256×192）**；如现有机型屏幕比例不同，按显示网格适配，保留像素比例和安全区，不得拉伸成 16:9 导致螃蟹变形。
- 屏幕内部美术：像素角色、可读的 16×16 机关格、侧视平台、可区分材质的墙/石块/压力板/宝箱/怪物；禁止用纯色矩形永久代替正式游戏素材。像素贴图以整数倍最近邻缩放，避免线性过滤发糊。

## 3. 三层 360°阵列装饰方案

### 底层（使用频繁，玩家注意力中心）

- 主可玩 CRT 保持正前方醒目：机壳米白、薄荷绿电源灯，边框小贴纸，屏幕画面清楚可见。
- 底座增加镂空金属横梁、黄黑警示胶带、螺丝、插线板、横向电源线、软盘箱。
- 一侧放小复古磁带机/便携录音机与散落软盘，但不挡屏幕。

### 中层（连接与识别）

- 交错摆放薄荷绿、灰白、暗紫 CRT，比例大小不同，留通路视线。
- 局部串联 DATA CABLE，连接处增加小型通信模块、发光指示灯、原创编号。
- 一台屏幕显示噪声/故障，一台显示存档树，一台显示 LIVE 关卡内容。

### 高层（轮廓和地标）

- 保留可辨的「电脑塔」剪影，避开完全对称/整齐排列。
- 插入一个高对比的视觉地标：带黄黑标识的大屏/巨型贴纸板/吊牌（禁止挡住其他屏幕）。
- 背后增加软线缆、排风装置、电源小灯，旋转 360°时不露空、无漂浮配件。

## 4. 各屏幕与交互的视觉状态

| 状态 | 典型画面 | 反馈 |
|---|---|---|
| ACTIVE | 当前螃蟹所在关卡，实时更新 | 明显但克制的边框灯；相机对焦 |
| CONNECTED | 已探索过、可跳转 | 缓慢数据流、统一可识别图标 |
| LOCKED | 未解锁 | 断线条/锁形编号，避免复刻系统 UI |
| CORRUPTED | 受病毒污染 | 局部错位、色条、故障纹理 |
| SLEEP | 非活动设备 | 暗屏、细小电源灯，低成本渲染 |
| SECRET | 隐藏屏幕 | 特殊标签、稀疏闪灯作为线索 |

**穿梭规则**：螃蟹在 A 屏幕内到达已解锁的出口并互动，输入冻结、保存状态；3D 相机可后撤、绕开遮挡、沿电脑塔平移/旋转至 B 屏幕并推近；B 屏幕的侧视像素地图按指定出生点接管操控。不得出现螃蟹在机壳或底座上步行的动画。**正常游玩时优先给足当前屏幕占屏面积，不能为了展示电脑塔而让 2D 机关看不清。**

## 7. 分阶段交付（不要只把规划写在文档里）

### 阶段 A：1 个高完成度样板区域（与 2D 玩法切片协调）

选现有前侧 5-7 台电脑做样板：替换其中至少 3 台为不同造型，完成 12 项以上有效美术细节（机壳贴纸、按钮、软盘、线缆、磁带机、挂牌、散热孔、灯等），至少 4 种有区别的屏幕状态，完成一套灯光。保证已有可玩性；为玩法开发书中的 BOOT / ARCHIVE 两台可玩电脑保留清晰无遮挡的屏幕和可靠的入口锚点。

### 阶段 B：360°全景完善

按照正面、背面、左侧、右侧、顶视五个角度检查堆叠与装饰。补足背面散热与接线，避免视觉断层；调整电脑前后纵深，避免像平面墙。

### 阶段 C：交互镜头联动

完成 ACTIVE / CONNECTED / LOCKED 的区分，并演示 A 屏幕到 B 屏幕过渡；过渡中相机认得目标电脑位置但螃蟹不走到实体外部。防止镜头穿过模型或迷失目标。

### 阶段 D：优化和交付

发布可运行版本，附 `before/after` 对照截屏、正反左右顶视截图、实际模型授权表、FPS 与内存概况，明确任何因下载权限而缺失的资源，不允许用占位截图冒充成品。

## 10. 与新版游戏玩法开发书的接口约束（v1.1 新增）

1. **显示层与玩法层分离**：电脑是 `computer_id` 唯一标识的 3D 壳体与屏幕展示节点；关卡是 `level_id` 唯一标识的 2D 世界。两者通过映射配置连接，而不是写死在模型里。
2. **物理与画面分离**：2D 侧视地图的碰撞、石块、怪物、水位等均在 2D 世界计算，不受 3D 电脑旋转、倾斜、缩放影响。电脑就算倒着摆，玩家仍看到正确朝向、可正常操控的 2D 关卡画面。
3. **输入状态明确**：`PLAY_2D` 只控制屏幕中的螃蟹；`TRANSITION_3D` 冻结角色输入；`ARRAY_VIEW` 才允许观察/选择电脑阵列。不能让同一按键同时转动电脑塔和移动螃蟹。
4. **像素渲染**：默认采用 4:3 的低分辨率像素画布（建议 320×240，16×16 图块），按实际 CRT 屏幕区域进行等比贴合与安全区裁切；小屏设备可放大当前屏幕或隐藏部分外部 UI。
5. **真实展示**：非活动屏幕可显示缓存、关卡预览、故障或锁定画面，但不能把纯 UI 色块假装成已开发完成的 2D 游戏关卡。
6. **同一层级的文档优先级**：几何阵列、颜色、素材与装饰以本书为准；角色操控、机关规则、关卡数据、跨屏状态与测试以《CRT CRAB 游戏玩法开发书 v1.0》为准；发生冲突时保留不可违背的两条事实——多层 360° 电脑阵列不删，螃蟹永不离开屏幕。
