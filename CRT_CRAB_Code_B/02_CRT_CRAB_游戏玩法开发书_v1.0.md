# 《屏幕群岛 / CRT CRAB》游戏玩法开发书 v1.0

> 执行对象：Codex / 项目程序与关卡设计。**请先阅读场景执行单 v1.1，再阅读本文**。任务是改造现有可运行项目，不是重新制作一个无关游戏。此文是**待实施的设计规范**，不是已完成清单。
>
> 基础定位：**多层 360° CRT 电脑阵列（3D） + 电脑屏幕内部的 2D 侧视像素动作解谜 + 跨屏幕世界状态联动**。玩法受《钻石狂潮 / Diamond Rush》的环境解谜、隐藏收集和机关链条启发，但应使用原创关卡、原创角色、原创图形与机制组合。

## 0. 不可违背的设计边界

1. **保留三层以上、360°错落堆叠的复古电脑阵列。** 不是电脑墙、办公室、普通地牢背景；外部模型负责世界地图、空间结构、过场和视觉识别。
2. **螃蟹永远只存在于一块电脑的屏幕画面中。** 绝对没有爬出显示器、跑上机壳/桌面/底座、再跳入另一块屏幕的玩法。
3. **屏幕内部为 2D 侧视像素动作解谜。** 横向移动、跳跃、攀爬、推拉、滚石与压力板。不是普通俯视 ARPG，也不是 3D 低模平台跳跃。
4. **相机双层而非单一追尾。** 2D 关卡内是跟随螃蟹的正交视角；跨屏时外部 3D 相机围绕电脑堆叠移动到目标显示器；游玩时以 2D 角色和机关清晰可辨为首要目标。
5. **跨屏不是换皮选关。** A 屏幕中的行动必须能影响 B/C 屏幕的门、机关或通路，且状态可靠保存。
6. **继承现有仓库。** 先识别真实技术栈、文件结构与现有能力；不得凭空假定 Godot、Three.js、Unity 中的任一引擎，更不能未经理由整库重写。
7. **禁止“只有会动的占位方块”。** 可以在开发初期用基础图形做物理原型，但垂直切片验收时需要像素角色和可区分的正式机关表现。

## 1. 核心游戏循环

**观察屏幕里的障碍与宝箱 → 探索与躲避 → 操作石块/机关或打怪 → 找到屏幕出口/信号 → 转到另一台电脑 → 改变共享世界状态 → 返回或前往新屏幕 → 获取宝箱与能力 → 揭开更大的秘密。**

玩家目标同时有三层：
- **短目标（10–60 秒）**：抵达一处平台、避开落石、触发一个按钮、击败挡路小怪。
- **中目标（2–6 分钟）**：解开一台电脑的组合谜题、打开宝箱、解锁新出口。
- **长目标（10–30 分钟）**：通过多屏联动打通一片电脑阵列，找到章节核心记录并击败守关 Boss。

设计时不可依赖单纯杀敌刷数值填充时长；**以机关 45%、探索收集 25%、战斗 20%、剧情揭秘 10% 作为目标体验权重**，不是精确计时指标。

## 2. 输入、角色与移动

### 2.1 默认键位（保留兼容与可重映射）

| 输入 | PLAY_2D 中的作用 | 备注 |
|---|---|---|
| A/D / ←→ | 左右走动 | 螃蟹水平侧移，朝向视觉自然变化 |
| Space | 跳跃 | 允许简短跳跃缓冲与离地宽限（见参数） |
| W/S / ↑↓ | 梯子、上下平台、选择上下接口 | **不得**同时作为任意 2D 飞行移动 |
| J | 钳击 | 短距离近战，兼容键位配置 |
| E 或 K | 互动 / 夹取 / 推拉 | 目标靠近且朝向匹配才执行 |
| Shift | 横向冲刺 | 中期解锁，第一切片可以只预留输入与动画 |
| Tab | 阵列地图 / 跨屏关系图 | 可暂停 2D 操作；地图不等于在 3D 机壳上走路 |
| R | 重置**当前谜题** | 不得清空章节永久收集与已开启宝箱 |
| Esc | 暂停与设置 | 与浏览器系统快捷键冲突需处理 |

### 2.2 初始能力与进阶能力

**第一版即必须可用：** 左右移动、跳跃、梯子、钳击、推动/拉动物体、互动、受伤无敌帧、开箱、出口传送。螃蟹需有待机、走动、跳起、下落、钳击、推拉、受击、死亡/重生的像素动画或明确过渡状态。

**后续解锁：** 横向冲刺（限时闸门 / 战斗闪避）、蟹壳防御（反弹特定投射物/重压机关）、信号蟹钳（特定终端建立跨屏连接）。不要把所有能力在第一分钟发给玩家。

### 2.3 建议移动调参（起始值，需试玩校准）

- 以 **16×16 像素格**作为可读机关设计基准；角色可大约为 16×16 或 20×16 像素（碰撞盒与视觉分离）。
- 行走速度约 `72–96 px/s`；跳跃可上升 `40–56 px`，水平跨越 `48–72 px`；重力与跳跃初速度由引擎/物理步长配套调出，不要把这些数字生搬硬套。
- 土狼时间（离开平台仍可跳）约 `0.08–0.12 s`，跳跃输入缓冲约 `0.08–0.12 s`。这些改善操作手感但不能破坏机关精确性。
- 交互距离从 `1–1.5` 个格子测试；以明确高亮、方向标识和可见判定范围为准。
- 只有在对象明确标注为可移动且空间有效时才允许推/拉；禁止一帧推穿两格或穿墙。

### 2.4 物理模型的选择

采用 **连续角色运动 + 格子对齐的机关对象**。

- 螃蟹移动和跳跃采用连续物理与碰撞。
- 石块、门、压力板、传送带、激光发射器等布局按 16px 网格定位；移动块按明确步距/速度行进，避免物理抖动导致解谜随机失败。
- 对确定性的机关（滚石落点、开关触发、石块压板）用受控状态机或可复现逻辑，不依赖不可控刚体混乱碰撞。
- 石块与敌人可以被机关共同检测，但要明确重量阈值及触发类型。

## 3. 场景/镜头/渲染的核心架构

### 3.1 两层世界、一个可操控角色

- **3D 阵列世界**：ComputerArray、ComputerInstance、ScreenSurface、ExteriorCamera、TransitionController、ScreenVisualState。
- **2D 可玩世界**：LevelSession、CrabPlayer、TileCollision、PuzzleObjects、Enemies、Treasures、LevelCamera2D。
- **共享系统**：ScreenRouter、WorldState、SaveManager、InputMode、AudioRouter。
- 3D 电脑可以旋转倾斜，**不得改变 2D 关卡的重力方向或按键**；屏幕显示坐标由映射层负责。
- **同一时刻只能存在一只由玩家控制的螃蟹**。其他显示器是缓存预览/锁定态/低频动态效果，不是复制的玩家。

### 3.2 屏幕比例和像素清晰度

- 建议可玩画布：**`320×240`，4:3，16px 图块**。备选 `256×192`。已有屏幕若非 4:3，应加安全边界或按实际视口裁切；**不拉伸角色**。
- 最近邻纹理过滤、像素对齐、整数倍缩放；场景像素和 UI 字体分开处理，避免 3D 远距观察时产生摩尔纹。
- 屏幕贴到 CRT 的可见显示面，而非整个机壳矩形；通过 UV/材质/可控贴面实现，注意遮挡、反射、发光强度与视野比例。
- 2D 游戏界面可在 `PLAY_2D` 时通过局部放大/镜头对焦提高可玩尺寸；小屏可提供「屏幕专注模式」，仍保留是某台 CRT 的视觉线索。

### 3.3 输入状态机

`PLAY_2D`（螃蟹可操作）→ `TRANSITION_3D`（输入锁定、保存状态、相机转场）→ `PLAY_2D`（目标关卡接管）；另有 `ARRAY_VIEW`（地图观察）与 `PAUSED`。

要求：切屏期间停止受伤/重复交互、只提交一次传送事件、目标出生点无碰撞重叠、镜头到位后才开放输入。

### 3.4 过屏完整时序

1. 螃蟹到达出口，检查其解锁条件与目标 screen ID；若不满足，显示缺少的前置条件。
2. 锁定输入并创建一次性 transition token，记录 A 的出入口、角色状态与机关世界事件。
3. 保存 A 的必要状态（已触发永久开关、宝箱、门、可保存的关卡谜题进度）。
4. 2D A 场景停止接受玩家输入；3D 相机后撤并找到 B 的 `screen_anchor`，沿可见路线移动，避免穿过机箱。
5. 预加载 B 关卡资源；根据 B 的 `spawn_id` 放置**同一个逻辑玩家实体**，清除残留速度/攻击碰撞。
6. 3D 相机推近 B 屏幕；完成后进入 `PLAY_2D`，播放进入反馈，再恢复输入。
7. 任何阶段失败，恢复到 A 的安全检查点并解除输入锁定；不丢失已提交的永久奖励。

**性能：** 只让当前关卡按完整频率运行；其他屏幕使用静态缩略图或受控低频画面，避免整座电脑塔每块屏幕都运行 AI 与刚体物理。

## 4. 可复用的机关库（按优先级开发）

| ID | 机关 | 玩家理解的规则 | 与其他物体联动 | 垂直切片优先级 |
|---|---|---|---|---|
| P01 | 可推拉数据石块 | 推拉后占据新格，挡路/压板 | 可被传送带推动，重块可触发重压板 | 必做 |
| P02 | 重力滚石 | 失去支撑后向下落；可在指定轨道滚动 | 压板、碎地、攻击敌人 | 必做 |
| P03 | 压力板 | 达到规定重量持续按住才触发 | 门、桥、激光 | 必做 |
| P04 | 机关门 | 由信号或钥匙打开 | 压力板、跨屏事件 | 必做 |
| P05 | 可破坏墙/地 | 有明确裂纹，不会误导玩家 | 钳击/落石/怪物撞击 | 第二轮 |
| P06 | 周期电流/激光 | 有警示节拍，开/关窗口可预测 | 推箱挡光、敌人误伤 | 第二轮 |
| P07 | 传送带/移动台 | 恒定方向，开关可反转 | 石块与敌人移动 | 第二轮 |
| P08 | 水位变化/漂浮物 | 开关改变液位与通路 | 浮板、电流失效（清晰标注） | 第三轮 |
| P09 | 密钥门/密码 | 需要指定物品或知识 | 宝箱、跨屏线索 | 第二轮 |
| P10 | 跨屏信号节点 | A 触发使 B 某对象状态变化 | 开门、桥、灯、运输带 | 必做 |

**统一机关规范：** 每种机关必须有 `idle/armed/triggered/reset` 或等价可观察状态，明确碰撞、声音、视觉反馈、保存策略和谜题重置策略。不能出现「踩了按钮但不知道发生什么」。

### 4.1 物体与环境作用优先于炫技

- 滚石可以压板/砸碎脆墙/击退敌人，但其掉落轨迹必须可预判，有落点警示。
- 重量判定以数据字段为准，如 `weight: 2` 的石块可压重压板，角色 `weight: 1` 不行；不要写死只认某个类名。
- 玩家钳击可击败小怪、打碎脆弱数据块，不可无条件砸毁全部机关。
- 机关谜题引入新规则时按「安全演示 → 单规则挑战 → 双规则组合 → 跨屏重组」递进。

### 4.2 防软锁要求（硬性）

- 石块进入不可恢复死角、钥匙被压住、角色落入封闭空腔等都必须能够通过**只重置当前谜题**恢复；永远保留安全检查点。
- 关键钥匙或能力不得因 R 重置消失；宝箱奖励事务性提交，开箱成功不能领取两次。
- 存在唯一解的机关，应提供至少一个可复现的解题路径并进行自动/手动回归测试。
- 任何无法返回的单向出口，都必须是有意设计并有明显提示。
- 默认无需像素级极限操作或看不见的死亡陷阱才能解谜。

## 5. 战斗与敌人

战斗要短促、具反馈且能参与谜题，不做漫长刷血。推荐螃蟹基础 `3` 颗生命心（可调），受击后短暂无敌，并在检查点重生；一关不因轻微失误重来全部谜题。

| 敌人 | 行为 | 直接打法 | 解谜用途 | 第一轮 |
|---|---|---|---|---|
| 数据虫 | 固定路线巡逻，遇障碍短暂停顿 | 1–2 次钳击 | 引诱撞开特定脆墙（需有行为提示） | 必做 |
| 弹窗怪 | 定时蓄力发射数据弹 | 观察节奏并攻击 | 其投射物可短路带标记的机关 | 第二轮 |
| 碎片怪 | 吞噬带标记的小数据块 | 控制距离，击中核心 | 清理特定障碍，也可能改变路径 | 第三轮 |
| 蓝屏核心（Boss） | 3 阶段攻击与场地变化 | 击活信号节点后露出弱点 | 战斗即大型组合机关 | 章节阶段 |

战斗规则：攻击前摇/碰撞盒/击退/受伤闪烁/音效明确；怪物掉落物不应成为非确定性的必需开门钥匙，关键掉落必须保证能获得。

## 6. 宝箱、收藏、成长和奖励

| 类型 | 内容 | 必须做到 |
|---|---|---|
| 普通补给箱 | 数据晶体、回血、可选消耗品 | 玩家有获得反馈和数量显示 |
| 机关宝箱 | 通过单屏组合谜题领取 | 解开后与开箱状态分别保存 |
| 隐藏宝箱 | 裂墙/假墙/回访路线 | 入口有可发现线索，非随机暗门 |
| 核心宝箱 | 永久能力、章节记录、重大道具 | 永久唯一领取，不可因死亡/重置重复刷 |

建议第一章 **9 个宝箱**：BOOT 1、ARCHIVE 2、POP-UP 1、RECYCLE 2、SIGNAL 2、ERROR 1。设计上至少 3 个可选宝箱、2 个需要回访/跨屏操作的宝箱。

**收集品功能必须真实存在**：晶体可用于开启支线机房、兑换装饰/视觉皮肤或触发记录解锁中的一个；避免只是 HUD 里的无用计数。第一版可以先选择单一用途，不引入复杂经济系统。

## 7. 跨屏幕机关是核心差异化机制

### 7.1 两种连接

- **移动连接（Portal Link）**：玩家从当前关卡出口到指定电脑的 `spawn_id`；连接可双向或单向，必须在地图上标识。
- **状态连接（Signal Link）**：当前电脑内的开关、道具或敌人事件改变另一台电脑的物体状态；玩家不一定立即前往目标电脑。

**示例：** ARCHIVE 的黄色压力板被数据石块压住 → 产生 `signal_archive_gate = true` → SIGNAL 的左门打开；若设计为永久解锁则记录世界旗标，若设计为持续压力则离开后要通过**稳定持久的石块位置记录**保持有效。**不得出现离开关卡就把板上的石块重置，导致异屏门错误关闭。**

### 7.2 链接图示（示例，不是屏幕的物理排列图）

```text
BOOT ─────┬────> ARCHIVE ──────> RECYCLE ──────> SIGNAL ─────> ERROR
          └────> POP-UP ─────────────┘               ^
                      └──(事件)──> SIGNAL 的供电开关 ──┘
```

首章可允许回访 BOOT/ARCHIVE/POP-UP 取隐藏宝箱；3D 电脑空间中看得见不代表已解锁可进入。

### 7.3 数据约定（示意；字段名适配现有技术栈）

```json
{
  "computer_id": "crt_archive_02",
  "level_id": "archive_01",
  "visual_status": "CONNECTED",
  "portals": [
    {"portal_id": "archive_to_recycle", "target_computer_id": "crt_recycle_04", "target_spawn_id": "entrance_left", "requires": ["archive_gate_open"]}
  ],
  "emits": [{"event": "archive_plate_activated", "flag": "signal_archive_gate", "persist": "while_supported"}]
}
```

- `computer_id` 是实体 CRT 身份，`level_id` 是内部 2D 地图身份，`portal_id` 是连接身份，`spawn_id` 是目标关卡安全出生点；不得混用。
- `persist` 至少分 `permanent`（永远保留）、`while_supported`（依赖保存中的物体/机关状态）、`reset_on_reentry`（重进重置）、`session_only`（当前尝试有效）。
- 路由事件统一处理；禁止 A、B 关卡互相直接访问对方的具体节点，造成加载顺序错误。
- `visual_status` 与玩法解锁状态相关联但不完全等同：`CORRUPTED` 可以同时是已解锁、可进入的关卡。

## 8. 六台电脑的第一章设计：BOOT / 失联的电脑群

> 第一章预计 20–30 分钟是**设计目标，需试玩验证**，不应伪称为实测结果。六台均为完整小地图，而不是把六台电脑做成 six 个静态过场。

| 电脑 / 关卡 | 主要教给玩家的规则 | 关键挑战 | 敌人 | 宝箱 | 离开条件 |
|---|---|---|---|---:|---|
| 01 BOOT 启动区 | 左右、跳、推箱、交互、出口 | 用箱子压板打开门 | 无 | 1 | 激活启动端口 |
| 02 ARCHIVE 档案仓库 | 滚石+落差+压力板 | 推落重石并压住常驻压力板 | 数据虫 | 2 | 档案密钥激活 |
| 03 POP-UP 弹窗区 | 战斗、定时危险、破坏物 | 引导敌弹击中短路开关 | 弹窗怪 | 1 | 解除干扰源 |
| 04 RECYCLE 回收站 | 假墙、可破坏地形、隐藏路线 | 收集碎片拼回通行路径 | 数据虫/碎片怪（可延期） | 2 | 修复废弃端口 |
| 05 SIGNAL 信号中心 | 跨屏联动、回访 | ARCHIVE 重压板 + POP-UP 供电 + 本地桥梁 | 弹窗怪 | 2 | 三信号齐备 |
| 06 ERROR 错误核心 | 机关型 Boss | 躲避攻击引导破坏 3 节点 | 蓝屏核心 | 1 | 击败 Boss，获得章节记录 |

### 8.1 BOOT：新手关（预计 3–4 分钟）

1. 螃蟹出现于安全的平台；靠移动获得第一个晶体，玩家无需文字教学也能发现方向。
2. 一个宽度不大的沟壑教会跳跃，旁边有可返回的安全路。
3. 一块可推动的数据箱停在压力板旁；把它推上板，门打开；通过贴图、灯和声音教会「重量 → 开门」。
4. 主路可直接通向出口；一处轻微隐藏平台藏着普通宝箱，教会探索有奖励。
5. 触发 PORT_01，演示首个 3D 电脑转场，目标 ARCHIVE；转场前/后螃蟹始终在 2D 屏幕画面里。

### 8.2 ARCHIVE：滚石档案仓库（预计 4–6 分钟）

1. 一开始能看到高台上的重石、下方重压板与一扇锁门；玩家看到目标而非猜目标。
2. 通过推箱搭建上台阶的路线，钳击清理可破坏小块，抵达重石左侧。
3. 把重石沿确定的斜坡推下，重石受重力落入轨道并压住重压板；开门、有明确视觉信号。
4. 石块落错轨道、被玩家误推死角时，`R` 只重置这一谜题，不重置已获得的宝箱。
5. 通路分成档案密钥主线与假墙后隐藏宝箱支线；出口通向 RECYCLE，且永久/维持性信号发送给 SIGNAL。

### 8.3 POP-UP：故障弹窗战斗（预计 3–4 分钟）

1. 沿途的错误窗口会作为贴图障碍和敌人预警，不做大面积遮挡角色的真系统弹窗。
2. 弹窗怪先在无陷阱安全区演示蓄力与发射；玩家学会躲避/钳击。
3. 在机关区，敌弹能命中标识清楚的短路开关，使持续电流暂时关闭。
4. 玩家利用冷却时间通过，清除干扰节点，给 SIGNAL 发出 `popup_power_restored`。
5. 一处宝箱需要观察敌人巡逻节奏，并非无脑打怪后掉落。

### 8.4 RECYCLE：碎片回收站（预计 4–5 分钟）

1. 玩家看到被废弃数据堵塞的路径，地形显著表现出裂痕/可破坏标识。
2. 利用落石/钳击开路；只有明确标记的碎片可破坏。
3. 主线通过收集 3 个修复部件解锁端口；其中一个可通过可选机关获得，避免全地图乱找。
4. 隐藏支线有第二个宝箱，奖励线索提示 SIGNAL 的多屏机关。

### 8.5 SIGNAL：多屏联动（预计 4–6 分钟）

1. 玩家进入后看到有三个输入信号的门：重压板、恢复供电、局部通路；每个输入独立灯号展示来源。
2. 若 ARCHIVE 与 POP-UP 事件尚未满足，提示对应电脑名称和线缆，不用谜语式 UI 瞎猜。
3. 通过本地移动平台/推箱谜题完成第三条件，桥梁形成。
4. 一条隐藏路线需要回访 ARCHIVE 的未取宝箱或后期能力，强化不同屏幕相互关联。
5. 关卡通向 ERROR，外部 CRT 阵列灯号同步依次亮起。

### 8.6 ERROR：章节 Boss（预计 4–6 分钟）

1. 首段在安全地带展示蓝屏核心的蓄力直线攻击，玩家能理解闪避节奏。
2. 中段引导核心投射物击碎 3 个被标记的信号节点；每次破坏改变一小块平台结构。
3. 最后阶段弱点露出，允许螃蟹用钳击造成伤害；明确血量或受伤反馈。
4. 失败从 Boss 前检查点重来，已完成的前五台电脑不会回档；通关获得一条新的世界记录与下一章节的线索。

## 9. 关卡数据、状态与存档

### 9.1 至少需要以下对象系统

- `GameSession`：玩家生命、能力、当前电脑、输入模式、检查点。
- `ComputerRegistry`：每台实体 CRT 的位置、朝向、显示材质与 level 映射。
- `LevelDefinition`：2D TileMap/碰撞图、出生点、端口、机关、敌人、宝箱定义。
- `PuzzleState`：本关可重置机关快照和步骤状态。
- `WorldFlags`：跨屏永久状态与持续受支撑事件。
- `TreasureLedger`：以独立 `chest_id` 防止重复领取。
- `ScreenRouter`：受控传送、回滚与目标出生点校验。
- `SaveManager`：版本化序列化、自动存档与失败恢复。

### 9.2 存档示例

```json
{
  "schema_version": 1,
  "current_computer_id": "crt_boot_01",
  "current_level_id": "boot_01",
  "spawn_id": "checkpoint_02",
  "player": {"hp": 3, "abilities": ["pinch", "push_pull"], "crystals": 13},
  "world_flags": {"archive_gate_open": true, "popup_power_restored": false},
  "collected_chest_ids": ["boot_chest_01"],
  "level_persistent_states": {
    "archive_01": {"heavy_boulder_01": {"grid_x": 12, "grid_y": 8}, "heavy_plate_01": true}
  }
}
```

**注意：** JSON 只是跨语言结构示例，不要求已有仓库照搬命名或数据存储方式。实现时应提供版本迁移和缺字段默认值。

### 9.3 重置/死亡/离开/加载的状态矩阵

| 事件 | 永久宝箱 | 永久钥匙/技能 | 当前谜题临时物体 | 持续信号/石块 | 已开放传送 |
|---|---|---|---|---|---|
| 按 R 重置谜题 | 保留 | 保留 | 回到谜题起点 | 根据谜题依赖重新计算 | 保留 |
| 角色死亡 | 保留 | 保留 | 回检查点或谜题快照 | 从保存位置/规则恢复 | 保留 |
| 离开当前屏幕 | 保留 | 保留 | 按该谜题定义保存或重置 | 必须按持久策略处理 | 保留 |
| 重新加载游戏 | 保留 | 保留 | 从存档或安全起点恢复 | 恢复可复现状态 | 保留 |

**禁止的 bug：** 压板在 A 被石块压住，切到 B 后门打开，但重启游戏门莫名其妙关闭；或者箱子重复领取、怪物重复掉落关键钥匙。

## 10. 美术、声音与 UI（与场景书保持一致）

### 10.1 像素美术规范

- 4:3 侧视地图，目标 `320×240`，16×16 Tile。推荐先统一 1 套实际 tile atlas、1 组螃蟹动画、1 组敌人 sprite、1 组机关 sprite，不要一屏一种互相冲突的像素密度。
- 像素画可使用色彩鲜明但克制的电子青、酸柠黄、莓果粉、墨蓝紫；每关主题不同，但建筑/平台、可推物、危险物、可交互物的视觉语义必须一致。
- 游戏内部不画写实机壳或三维电脑场景来替代地图；外部 CRT 由独立 3D 美术负责。
- 不要混用无抗锯齿真像素图与模糊笔刷纹理；避免闪烁彩噪、强 Bloom、满屏故障特效影响机关判断。
- 互动反馈：压力板发光、门齿轮移动、石块有重量感/落地尘点，宝箱开启动画有清晰奖励弹出。

### 10.2 建议 HUD

在屏幕近景模式中显示：生命心、晶体数、当前电脑 ID、宝箱收集 `x/y`、短提示。暂停菜单含设置/重开谜题/返回阵列地图。3D 外部 HUD 只保留必要的电脑名称、连接状态与提示，不遮住主屏幕。

### 10.3 声音

- 螃蟹侧移脚步、跳跃着地、金属钳击、箱体摩擦、石块落地、压板卡嗒、传输握手、打开 CRT 的轻微嗡鸣、宝箱奖励与受伤提示。
- 每关有可辨的低强度环境循环；危险提示要优先于背景音乐，静音玩家也必须看得懂机关。
- 若仓库已有音效系统就复用；素材需记录授权来源，避免直接挪用其他游戏声音。

## 11. 实现顺序与里程碑（不允许一步宣称全部完成）

### M0：仓库审计 + 备份 + 技术适配

**先输出：** 使用的引擎/渲染技术、项目运行命令、目录结构、现有屏幕路由、3D 镜头、旧角色控制与存档情况。创建可回退的版本分支或提交。列出会保留/替换的模块，禁止未经核对强行迁移技术栈。

**通过条件：** 原有项目能运行，有 baseline 截图与控制台记录；没有删除电脑堆叠、现有资产与已能工作的转场。

### M1：单屏 2D 操作样板

制作 BOOT 单屏：螃蟹侧视走跳、推动一块数据箱、压力板开门、一个宝箱、出口。使用临时素材可以调手感，但必须预留正式 sprite/atlas 接口。

**通过条件：** 玩家能完整做出「移动→解谜→开箱→出门」的闭环，失败可以局部重置，角色不会穿墙/卡入地面。

### M2：两屏可玩的完整垂直切片（首要交付）

接通 BOOT + ARCHIVE 的两个真实 2D 关卡；实现石块、重力落下、持续压力板、跨屏事件、前后转场与回访存档；加一个数据虫、至少两个实际宝箱。将正式/接近正式的像素素材置入画面。

**通过条件：** BOOT → ARCHIVE → BOOT → ARCHIVE 往返，螃蟹从不出屏幕；已开宝箱不能重复获得；ARCHIVE 的重石和 SIGNAL 预留旗标状态可持久恢复；有视频或逐步截图证据。

### M3：场景美术升级与联动

同步执行场景执行单的样板区域：前侧 5–7 台电脑中至少 3 台换成不同模型，3–5 组有实际锚点的线缆和环境装饰；活动屏幕为真实 2D 像素画面，其他屏幕有可区分的休眠/锁定/预览表现。

**通过条件：** 五视角（前后左右顶）截图；两台实玩屏幕无纹理拉伸/遮挡，镜头转场不穿模；真实性能记录与模型署名表。

### M4：扩展第一章

依次加入 POP-UP、RECYCLE、SIGNAL、ERROR；优先完善跨屏信号玩法，再增加新敌人、特殊机关、Boss。每加一关都通过可解性测试，不允许复制同一地图仅换背景色。

**通过条件：** 六个真实可玩的地图，9 个宝箱，3 类普通敌人（可按优先级调整并记录差异）、1 个 Boss，主线可通关，至少 3 个隐藏/可回访奖励。

### M5：打磨、适配与发行候选

优化键位、暂停、存档、音量、画面清晰度、性能；写游戏内操作教学与玩家提示；完整回归测试，修复软锁与跨屏状态 bug。若是网页项目，验证桌面浏览器下缩放、刷新/重载、焦点丢失等问题；手机支持视项目既有要求而定，不能假报已适配。

**通过条件：** 无阻断游玩的已知 bug；能通过完整主线并重开；资源授权可追溯；性能指标需记录测试设备和真实数据。

## 13. 反例清单（Codex 避坑）

- ❌ 把屏幕内做成自由 3D 小螃蟹跳平台，放弃侧视像素玩法。
- ❌ 把 3D 电脑塔删除，用平面选关菜单替代。
- ❌ 在显示器外面出现一只可以爬机壳的实体螃蟹。
- ❌ 只让 3D 电脑堆旋转，玩家一直在同一块静态屏幕里玩。
- ❌ 每台屏幕只是不同颜色的网格 + 矩形平台，没有差异化机关。
- ❌ 用随机物理致使滚石落点不稳定，解谜只能靠反复碰运气。
- ❌ 把所有机关变成「靠近按 E 就开门」，没有环境组合。
- ❌ 给每台 CRT 都运行独立全速 2D 游戏，导致严重性能下降。
- ❌ 切屏时将保存数据丢失、箱子重复领奖或解锁门复位。
- ❌ 宣称已实现跨屏玩法，实际只是镜头移动或静态贴图切换。
- ❌ 不真实下载模型，却用 Sketchfab 截图或空占位作为交付。
- ❌ 直接照搬《钻石狂潮》关卡、美术、音效或《绝区零》品牌图形。
